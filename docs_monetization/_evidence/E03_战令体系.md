## 2. 战令结构（问题 1）

### 2.1 数据层级（真值）

```
BattlePassDescription（赛季，MyEnumItem: id + index）
├─ StartTs / EndTs                      赛季时间窗（ms 时间戳）
├─ PremiumCryptoCoinsPrice (int)        Premium 售价（B-Coin）
├─ Pages : BattlePassPageDescription[]  ← 页（唯一带解锁阈值的层级）
│   ├─ UnlockThreshold (int)            页解锁阈值（含义见 §5.3）
│   ├─ FreeRewards    : FreeRewardDescription[]
│   └─ PremiumRewards : PremiumRewardDescription[]
├─ StartingRewards : PremiumRewardDescription[]   购买即送的奖励
├─ MainReward      : PremiumRewardDescription     最终奖励（Final Reward）
├─ RepeatableReward: RepeatableRewardDescription  无限奖励
├─ FreeRewards  : FreeRewardDescription[]         扁平免费表（派生）
├─ FreeRewardPageIndexes : int[]                  扁平表→页映射（派生）
├─ PremiumRewards : PremiumRewardDescription[]    扁平付费表（派生）
└─ PremiumRewardPageIndexes : int[]               扁平表→页映射（派生）
```

`[实证] dump.cs:129404-129491`（11 个只读字段 + 全部 getter + **9 参** `.ctor`：`id, index, startTs, endTs, premiumCryptoCoinsPrice, pages, startingRewards, mainReward, repeatableReward`，行 129446）
`[实证] dump.cs:129569-129602 BattlePassPageDescription`（3 字段：`UnlockThreshold`/`FreeRewards`/`PremiumRewards`）

**关键结构事实**：
1. `BattlePassDescription` 的 11 参构造函数**只接收 pages/starting/main/repeatable**，不接收 `FreeRewards`/`PremiumRewards`/`*PageIndexes` → 这 4 个是**由 pages 聚合出的派生索引表**。`[推断]` 聚合链：遍历 `Pages[i]` 的每条奖励 → 追加到扁平表，并把 `i` 追加到对应 PageIndexes；`Claim*(Message)` 用的 `RewardIndex`（`dump.cs:208019`）就是**扁平表下标**。`[实证] dump.cs:513434 FillByPage(pageIndexes, pageIndex, type, rewards)` 证实运行时是按 PageIndexes 反查扁平表取格子。
2. **批次/页的划分是"美术+解锁"单位，不是"等量格子"单位**：页内免费/付费奖励数量由数据任意决定（`FillByPage` 按 index 过滤，无等分逻辑）。`[推断]`
3. **没有 Tier / Level / 等级线**：全库 grep `BattlePassTier|BattlePassLevel|SeasonPass` **零命中**。战令的"进度"= 点数余额 + 已花费点数（§5），不存在"升到 X 级解锁第 N 档"。`[实证] grep 无结果`
4. 赛季切换：`BattlePassRules.TryGetActiveBattlePass(now,…)` / `TryGetPreviousBattlePass(now,…)` `[实证] dump.cs:194194/194203`；`BattlePassDescriptionExtensions.IsActive` `[实证] dump.cs:5455`；`BattlePassSkinRules.IsUnavailableBattlePassSkin(skin, now)` 用 `_skinsEndTs` 判定"赛季过期皮肤"。`[实证] dump.cs:514360/514369`

## 4. 四条（实为五类）奖励轨：Free / Starting / Premium / Main(Final) / Repeatable（问题 2）

### 4.1 五类枚举真值

| 值 | 枚举 | 含义 |
|---|---|---|
| 0 | `Free` | 免费轨（点数购买） |
| 1 | `Repeatable` | 无限轨（点数购买随机物品） |
| 2 | `Starting` | 购买 Premium 时的"立即到账" |
| 3 | `Premium` | 页内付费轨 |
| 4 | `Main` | 最终奖励（Final Reward） |

`[实证] dump.cs:194177-194186 BattlePassRewardType`

### 4.2 五轨对照表

| 维度 | Free | Starting | Premium | Main / Final | Repeatable |
|---|---|---|---|---|---|
| 解锁条件 | 页已解锁（`IsPageUnlocked`）+ 点数足够 | **购买 Premium 即触发** | **已购 Premium** + 页已解锁 + 点数足够 | 已购 Premium **且** 其他 Premium 奖励全部已领 | 页已解锁（？见 Unknown）+ 点数足够 + 地点允许 |

## 13. 结论摘要（5-15 行）+ 三条最有价值发现

1. **战令是"点数即货币、花费即进度"的双用途设计**：`BattlePassPointsModel` 存余额，`IsPageUnlocked(bp, spentPoints, pageIndex)` 用**已花费**判定页解锁（`dump.cs:194239`），页面锁态直接显示 `Spent {0}/{1}`（`loc:battle_pass_rewards_page_spent`）——没有等级/Tier 概念（全库 grep 零命中）。
2. **五条轨**：Free（点数买固定道具/随机池）、Starting（买 Premium 立得）、Premium（买 Premium 解锁的 9 类皮肤+B-Coin）、Main/Final（集齐全部 Premium 后领取，仅最后一页）、Repeatable（无限次点数换随机道具，仅最后一页）。
3. **Premium+ = 补差买断**：`Instantly unlocks and grants all Premium Battle Pass rewards`（loc），价格有"实际价 + 划线原价"两态（`dump.cs:512161`），依赖 `GetPremiumWithRewardsPrice` vs `…FullPrice`（`dump.cs:194212/194215`）；已购 Premium 后按钮仍在，领完全部付费奖励后隐藏（`dump.cs:511499`）。
4. **定价完全走 B-Coin**：赛季只有 `PremiumCryptoCoinsPrice` 一个价（`dump.cs:129412`）；B-Coin 靠 6 档充值包（`CryptoCoinsPack0..5` + `Tier499/999/1499/1999/2999/4999`）获得；余额不足时 `BuyCoinsNotEnough → TryGetCoinsPack` 自动选档补差（`dump.cs:448552-448558`）。**没有任何指向战令的 Steam SKU**。
5. **上限 + 换州清空构成"当期消费压力"**：`BattlePassConfig.MaxPoints` 封顶、`battle_pass_currency_balance` 显示 `N/Max`、换州（含 Surrender to Feds）弹窗提示 `Accumulated Battle Pass currency will be lost: {0}`。
6. **本地配置里"能看到的真值"只有 6 个**：赛季 1 个（`battle_pass_1` / SeasonArt_Chemical）、随机池 4 条（room_key/phone/infinite_reward_1/safe_key）、提示阈值 72 小时、横幅行容量 5、货币稀有度 Legendary、20 条文案映射；价格与页数全部未提取（IL 常量）。
7. **`BattlePassErrors` 只有 1 条**（`no_inventory_space`）→ 说明绝大多数拒绝发生在客户端 `GetRestriction` 的 6 种原因里。

**最有价值的三条发现**

- **A. "花费即进度"（spent-as-progress）而非"经验升级"**：`IsPageUnlocked(…, int spentPoints, …)` 的入参签名是硬证据（`dump.cs:194239`），配合页锁 UI 文案 `Spent {0}/{1}`（`loc:battle_pass_rewards_page_spent`）与 `GetSpentPoints`（`194242`）。这意味着**玩家必须消费点数才能推进战令**，天然把"留存"与"消费"绑成一件事；同时叠加 `MaxPoints` 上限 → 囤积无收益，逼当期花完。
- **B. Premium+ 是"按已领取进度折价的买断"**：`dump.cs:512161` 的 Tooltip 明写"实际价 + 划线全价（若部分奖励已领取）"，加上 `GetPremiumWithRewardsPrice(bp, model, awards)` 依赖已领状态（`194215`）——这是**完整的"进度折价"商业化模型**（越晚买越便宜，但已领的按原值扣减），也是战令最常见的二次变现点，本地证据链完整到可以直接复刻。
- **C. 付费墙被"地点"二次切分**：道具类奖励（Free 轨与 Repeatable）只能在 **Lenny's（枢纽）或聚落**购买（`loc:battle_pass_rewards_restriction`），战斗内还有 `BattlePassShopActionsRules` 的动作闸门（`dump.cs:398915`）；而皮肤类奖励不受地点限制。→ 设计意图是**用战令把玩家反复拉回社交枢纽**（提高暴露与转化），复刻时这条限制不能省。
