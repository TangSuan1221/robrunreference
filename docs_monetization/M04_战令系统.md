# M04 · 战令（Battle Pass）商业化拆解

> **一句话**：ROB RUN 的战令不是"一条免费轨 + 一条付费轨"，而是**两条轨 × 四种购买动作 × 一个一次性买断包**。它是本作**单位付费密度最高**的系统。
> **证据**：`out\il2cpp\dump.cs`（行号均标注）、`out\loc_en.txt`、`out\strings_game.txt`。

---

## 0. 一页结论（7 条）

1. **赛季 = 一个 `BattlePassDescription`**，字段只有 8 组：`StartTs / EndTs / PremiumCryptoCoinsPrice / Pages[] / StartingRewards[] / MainReward / RepeatableReward / FreeRewards[]+PremiumRewards[]`（后两者带页索引）。`[实证] dump.cs:129404-129441`
2. **奖励是按"点数价格"标的，不是白给**：`FreeReward.Price` 与 `PremiumReward.Price` 都是 `int`，玩家用战令货币（Battle Pass Points）"买"格子。`[实证] dump.cs:129518、129659`、`loc:battle_pass_not_enough_points_notification`
3. **付费轨有三层付费**：① 买 Premium（整季解锁）② 买 Premium+（**一次性发放全部未领的 Premium 奖励**，含 `StartingRewards`）③ **单格直购**（`PremiumReward.CryptoCoinsPrice`，不用点数、直接花 B-Coin 买这一格）。`[实证] dump.cs:129412、129661、512632-512675`
4. **`StartingRewards` 是"买了立刻到账"的钩子**：买 Premium 瞬间发放一批奖励，制造"立刻回本"感。`[实证] dump.cs:129416`、`BattlePassPurchaseRules.AddNotClaimedStartingRewards`（512662）
5. **`MainReward` 是"集齐制"**：文案 `The main Battle Pass reward unlocks once all other premium Battle Pass rewards have been claimed.` —— 逼玩家把付费轨走完。`[实证] loc:battle_pass_rewards_main_tooltip_description`
6. **`RepeatableReward` 是点数回收器**：固定 `Price` + 一个随机物品池，**无购买上限**（`There is no purchase limit`），把溢出点数变成随机物品。`[实证] dump.cs:129901-129931`、`loc:battle_pass_rewards_repeatable_tooltip_description`
7. **换州即清空战令货币**：`battle_pass_leave_realm_points_lost = "Accumulated Battle Pass currency will be lost: {0}"`。这是**逼玩家在当前州内把点数花掉**的强设计，也是"州寿命"与商业化绑定的地方。`[实证] loc:battle_pass_leave_realm_points_lost`

## 1. 层级结构（Season → Page → Cell）

```
BattlePassDescription（赛季）
├─ StartTs / EndTs                       赛季窗口
├─ PremiumCryptoCoinsPrice               买断价（B-Coin）
├─ Pages[ BattlePassPageDescription ]    页
│   ├─ UnlockThreshold                   ← 解锁该页所需的**已花费**点数（不是累计获得）
│   ├─ FreeRewards[ BattlePassFreeRewardDescription ]
│   └─ PremiumRewards[ BattlePassPremiumRewardDescription ]
├─ StartingRewards[ PremiumReward ]      买 Premium 立刻送
├─ MainReward        PremiumReward       集齐全部付费奖励后解锁
├─ RepeatableReward  RepeatableReward    点数→随机物品（无限次）
├─ FreeRewards[] + FreeRewardPageIndexes     免费轨的"平铺视图"
└─ PremiumRewards[] + PremiumRewardPageIndexes  付费轨的"平铺视图"
```

`[实证] dump.cs:129404-129441、129569-129602`

**为什么同时有"嵌套"和"平铺"两套**：`Pages[].FreeRewards` 是**页内布局**，`FreeRewards[] + FreeRewardPageIndexes` 是**跨页聚合视图**（UI 上"连续滑动的奖励带"）。两者内容相同、索引不同 → 客户端可同时渲染"分页"与"整条长带"。`[推断，依据双结构 + BattlePassRewardsPageRules/RowRules 两个 Rules 类]`

## 2. 四种奖励类型（决定"卖什么"）

### 2.1 免费奖励 `BattlePassFreeRewardDescription`

| 字段 | 类型 | 含义 |
|---|---|---|
| `Price` | int | **点数价格**（免费轨也要花点数） |
| `Item` | `InventoryItemWithAmount?` | 静态物品（可空） |
| `RandomItemFunc` / `RandomItem` / `IsRandom` | `BattlePassRandomItemDescription` | 随机物品池 |

构造工厂两个：`Static(price, item, amount)` / `Random(price, randomItem)`。`[实证] dump.cs:129514-129564`

### 2.2 付费奖励 `BattlePassPremiumRewardDescription`

| 字段 | 类型 | 含义 |
|---|---|---|
| `Price` | int | 点数价格 |
| **`CryptoCoinsPrice`** | int | **单格直购价（B-Coin）** ← 关键 |
| **`CryptoCoins`** | int | **本格奖励就是 B-Coin**（返币格） |
| 9 类外观槽 | `BodySkin / FBodySkin / BagSkin / MaskSkin / KeychainSkin / WeaponSkin / Emotion / Car / Helicopter` | 与 `ShopPackItemDescription` **完全同构** |

`[实证] dump.cs:129655-129714`

> **这是本作最"狠"的一处设计**：同一格奖励有**两个价格**（点数价 + B-Coin 直购价），且**付费轨里还夹着 B-Coin 返币格**。玩家在"肝"与"氪"之间被反复引导，且返币格制造"回血"错觉。

### 2.3 主奖励 `MainReward`

- 类型同 `PremiumReward`，但只有 1 个，且**解锁条件不是点数，是"全部付费奖励已领取"**。
- `ClaimMainReward` 独立动作（`BattlePassPurchaseRules.ClaimMainReward`，512678）。
`[实证] dump.cs:129418、loc:battle_pass_rewards_main_tooltip_description、loc:battle_pass_main_reward_spent`

### 2.4 可重复奖励 `BattlePassRepeatableRewardDescription`

| 字段 | 含义 |
|---|---|
| `Price` | 每次消耗点数 |
| `RandomItem` | 随机物品池 |

**无次数上限**（文案明示）。作用：① 消化溢出点数 ② 给"战令末期"一个继续玩的理由 ③ 免费玩家也能持续获得物品。`[实证] dump.cs:129901-129931、loc:battle_pass_rewards_repeatable_tooltip_description`

## 2.5 五条奖励轨（官方枚举，不是四条）

`BattlePassRewardType` 枚举共 **5 值**：`Free / Repeatable / Starting / Premium / Main`。`[实证] dump.cs:194177-194186`

| 维度 | Free | Starting | Premium | Main / Final | Repeatable |
|---|---|---|---|---|---|
| 解锁条件 | 页已解锁（按**已花费**点数）+ 点数足够 | **买 Premium 即触发** | 已购 Premium + 页已解锁 + 点数够 | 已购 Premium **且** 其他 Premium 奖励全部已领 | 页已解锁 + 点数够 + **地点允许** |
| 花费 | 该格 `Price` 点数 | 0 | 该格 `Price` 点数 | 0（领取） | `Price` 点数 |
| 次数 | 1（`ClaimedFreeRewards`） | 1 次/格 | 1（`ClaimedPremiumRewards`） | 1（`IsMainRewardClaimed`） | **无限**（只计 `ClaimedRepeatableRewardsCount`） |
| 动作 | `BuyFreeReward → SendItemRewardPurchase` | 随购买 `AddNotClaimedStartingRewards` | `BuyPremiumReward → SendPremiumRewardPurchase` | `ClaimMainReward` | `BuyRepeatableReward` |
| 存档字段 | `ClaimedFreeRewards:Set<int>` | 与 Premium 共用 | `ClaimedPremiumRewards:Set<int>` | `IsMainRewardClaimed:bool` | `ClaimedRepeatableRewardsCount:int` |
| 可失败原因 | PageLocked / NotEnoughPoints / NotAvailableHere | — | PageLocked / PremiumRequired / NotEnoughPoints | PremiumRequired / AllSkinsRequired | PageLocked / NotEnoughPoints / NotAvailableHere |

`[实证] dump.cs:229335-229356、194164-194174、512628-512723`

**注意**：免费轨的方法名是 **`BuyFreeReward`（不是 Claim）** → 免费轨同样是"花点数买"；`Claim` 只用于无需付费的 Main 奖励。`[推断，依据方法命名 + Claim 按钮只挂主奖励 dump.cs:514036]`

grep `BattlePassTier|BattlePassLevel|SeasonPass` **零命中**。战令的"进度"不是等级，而是 **`点数余额` + `已花费点数`** 两个计数器。`[实证]`

## 2.7 "花费即进度"（本作最反直觉的一处设计）

| 环节 | 方法/字段 | 证据 |
|---|---|---|
| 计算已花费 | `BattlePassRules.GetSpentPoints(bp, model, awards)` | dump.cs:194242 |
| 页解锁（入参就是 spentPoints） | `IsPageUnlocked(bp, **int spentPoints**, int pageIndex)` | dump.cs:194239 |
| 页进度 | `BattlePassRewardsPageRules.GetProgress(...)` | dump.cs:513422 |
| 页锁 UI | `BattlePassRewardsPageView.Spent`，Tooltip "已花费 / 解锁需花费" | dump.cs:513512 |
| 文案 | `battle_pass_rewards_page_spent = "Spent {0}/{1}"` | loc |

→ **"赚点数"不推进战令，"花点数"才推进**。配合 `MaxPoints` 上限（余额封顶）与换州清空，形成三方夹逼：**必须当期花掉，且花得越多解锁越深**。这不是常见的"经验条"，而是"消费条"。`[实证+推断]`

## 2.8 Premium+ = 按已领进度**折价**的买断

| 证据 | 内容 |
|---|---|
| `dump.cs:512161` | Premium+ 价格按钮 Tooltip：**"实际价 + 被划掉的原价（若部分奖励已领取）"** |
| `GetPremiumWithRewardsFullPrice(bp)` | 原价 | dump.cs:194212 |
| `GetPremiumWithRewardsPrice(bp, model, awards)` | **依赖已领取状态** → 折价 | dump.cs:194215 |
| `CanBuyPremiumWithRewards(...)` | 购买闸门 | dump.cs:194209 |
| `dump.cs:512150` | 标题 Tooltip："立刻拿到 (N)"——含主奖励的总数 |
| `dump.cs:512157` | 奖励容器 Tooltip："页内付费奖励**倒序**，然后是起始奖励" |

## 3. 四种购买动作（决定"怎么收钱"）

| 动作 | 方法 | 花什么 | 得到什么 | 证据 |
|---|---|---|---|---|
| **买 Premium** | `BuyPremium()` | B-Coin（`PremiumCryptoCoinsPrice`） | 解锁付费轨 + **立即发放 `StartingRewards`** | 512632 |
| **买 Premium+** | `BuyPremiumPlus()` | B-Coin（价格由 `Premium+` 档决定，见 M05/商店） | **一次性把全部未领付费奖励发完**（含 MainReward） | 512635、512657 |

## 4. 点数经济（BP 的"内循环货币"）

| 参数 | 字段 | 说明 |
|---|---|---|
| 点数上限 | `BattlePassConfig.MaxPoints` | 硬顶，防溢出 |
| 赛季开关 | `BattlePassConfig.IsEnabled` | 整季可关 |
| 页解锁阈值 | `BattlePassPageDescription.UnlockThreshold` | 累计点数到线才开页 |
| 格价格 | `FreeReward.Price` / `PremiumReward.Price` / `RepeatableReward.Price` | 三套价格 |
| 清空条件 | 离开州 | `battle_pass_leave_realm_points_lost` |

`[实证] dump.cs:129376-129400、129573-129592`

**获取途径**（客户端可见）：
- 文案 1：`Pull jobs across Looty Bay to rack up the Battle Pass currency`（干活给点数）
- 文案 2：`Battle Pass currency earned: {0}`（有统一的"获得"提示）
- `CheatSetBattlePassPointsMessage`（207990）证明点数是**服务端可写**的单一数值
- 具体"每个行为给多少"→ **[未知-服务端]**（抓 `BattlePassPointsData` 增量）

**设计读法（`[推断]`）**：
```
点数 = 行为货币（可肝、可清零）
  ├─ 花在 Free 轨 → 留存
  ├─ 花在 Premium 轨 → 已付费玩家的"二次投入"
  └─ 花在 Repeatable → 消化溢出，防止"点数控仓"
B-Coin = 付费货币
  ├─ 买 Premium → 解锁
  ├─ 买 Premium+ → 一次性买完
  └─ 买单格 → 卡点付费（差一格时最冲动）
```
**四种价格锚共存**（点数价/整季价/买断价/单格价），是本作战令"分层变现"的核心。

## 8. 设计读法（给主策的 6 条判断）

1. **战令 = 主变现引擎，商店 = 次级**。理由：BP 有 4 个价格锚 + 4 种购买动作 + 12 个状态闸门，而商店只有 1 个价格锚（`CryptoCoinsPrice`）+ featured 覆盖。
2. **"单格直购"是卡点付费**：玩家差最后一格时，用点数要肝、用 B-Coin 立刻到手。这是本作最容易被低估的付费点。
3. **`StartingRewards` 是"付费即时反馈"**：买完立刻弹一堆奖励，抵消"我买了一堆还没到手的东西"的悔意。
4. **`MainReward` 集齐制 = 沉没成本锁**：已经买了 Premium 的人，为了主奖励必须把整季走完 → 提升赛季留存。
5. **点数换州清零 = 强制消费**：配合"州寿命"，玩家不能在旧州囤点数等新赛季。这条同时是**反对跨州套利**的经济阀门。
6. **返币格（`CryptoCoins`）** 让付费轨"部分回血"，本质是**折扣券**，比直接打折更隐蔽、更少伤害价格体系。
