# M06 · 货币兑换、银行与脏钱流水线

> **一句话**：本作把"钱"做成一条**带汇率、带额度、带延迟、带抽水**的兑换管道：真钱 → B-Coin →（银行柜员兑换）→ Credits →（ATM 取现）→ 现金 →（洗钱台/第三方）→ Credits。**每一段都有闸门，且闸门参数全在服务端。**
> **证据**：E04（82 KB）+ 本文复核行号。

---

## 0. 一页结论（10 条）

1. **游戏里其实有 7 种"钱" + 1 个空值**，由 UI 枚举 `Currency` 权威定义：`DirtyCash / CleanMoney(Credits) / Crypto(B-Coin) / CopSalary / Chip / Clan / BattlePass`。`[实证] dump.cs:1866510-1866517`
2. **只有 DirtyCash 的符号是 ASCII `$`**，其余是 U+24xx 圈字母区/私用区字形 → 全部走**自定义字体图标**。`[实证] dump.cs:1866511-1866517、1868770-1868779`
3. **兑换只发生在银行柜员 NPC 身上**（`CurrencyExchangeAction`，需 `HasBankAccount`），不是一个独立菜单。`[实证] dump.cs:381403、181996`
4. **兑换 9 个参数**：4 个延迟（普通/点差 × 买/卖）、2 个限时额度、1 个单笔上限、1 个点差、1 个汇率周期。`[实证] dump.cs:63981-63997`
5. **双延迟是两套风控**：普通延迟卡"高频刷兑换"，点差延迟卡"吃 gap 套利"。合成一个参数必然顾此失彼。`[推断，依据 4 个字段的命名与拆分方式]`
6. **汇率是"服务端预生成的分期离散序列"**：客户端只拿到 `List<int> Rates` + `PeriodIndex`，报价过期会 `rate_out_date`；`Cheat...FutureRates` 可查**未来期**。`[实证] dump.cs:384557、206677、206606、10785`
7. **`ExchangeRateGap` 是乘性系数**（不是绝对价差）：由 `CurrencyExchangeDialogViewDescription` 的 Unity Tooltip 实证——Y 轴上限要覆盖 `ExchangeRateMax × (1+gap)`。`[实证] dump.cs:385419`
8. **客户端只有一个兑换函数**：`GetExchangePrice(int rate, bool isBuying)` —— 汇率本身客户端算不出来。`[实证] dump.cs:384700`
9. **额度用 `ExpiringResource` 原语**：服务端下发 `(ts, amount)`，客户端按 `Description(BeginTs, PeriodDuration, Count, Cooldown)` 自己算"还能换几次"。`[实证] dump.cs:214942-214948、64102`
10. **洗钱 = 4 条加成相乘**：基础速率 × 体量加成 × 模块加成 × 控制（区域）加成，且有 VIP / 帮派 / 区档三种外部乘区。**第三方（Lenny）抽成 vs 自建洗钱台不抽成**，是"付费买便利"的典型。`[实证] loc:laundering_by_*、dump.cs:172652/172781/7872/80027、loc:laundering_trader_info_description`

## 3. 九个参数逐个拆

| # | 字段 | 类型 | 设计意图 |
|---|---|---|---|
| 1 | `SellCryptoDelay` | long | 卖出后的**整体锁仓时间**：防"卖完立刻买回"套利 |
| 2 | `SpreadSellCryptoDelay` | long | 卖出**点差冷却**：当成交价触及点差档位时改用更长的时间 |
| 3 | `BuyCryptoDelay` | long | 买入后的整体锁仓 |
| 4 | `SpreadBuyCryptoDelay` | long | 买入的点差冷却 |
| 5 | `SellCryptoLimit` | `ExpiringResourceDescription` | 卖出**滚动窗口额度** |
| 6 | `BuyCryptoLimit` | `ExpiringResourceDescription` | 买入额度 |
| 7 | `CryptoCoinsPerTransactionLimit` | int | **单笔上限**（防一次性大额搬运/洗钱） |
| 8 | `ExchangeRateGap` | float | **乘性点差**：买 = rate×(1+gap)，卖 = rate×(1−gap) |
| 9 | `RatePeriod` | long | 汇率刷新周期 |

`[实证] dump.cs:63981-63997；ctor 参数序见 64049`

### 3.1 为什么"普通延迟"和"点差延迟"要分开（核心设计）

| 滥用类型 | 特征 | 用哪个参数拦 |
|---|---|---|
| 机器人高频刷 | 量大、单笔小、频率高 | `Sell/BuyCryptoDelay`（短延迟即可打断节奏） |
| 吃 gap 套利 | 精确在汇率切换点买入/卖出，赚 (1+gap) 与 (1−gap) 的差 | `Spread*Delay`（长延迟，让"下一期"到来时锁仓未解） |

若只有一个延迟：要么短到拦不住套利，要么长到正常玩家没法玩。**拆成两个 = 两类风控各自最优**。`[推断，但证据强：4 个字段并存 + 命名成对]`

### 3.2 玩家往返一次的真实成本

```
买 1 B-Coin：付 rate×(1+gap)
卖 1 B-Coin：得 rate×(1−gap)
往返一次净损 ≈ 2×gap（相对中间价）
```

→ **gap 就是兑换系统的真实"抽水率"**，且不需要改任何商品价格就能调——这是运营最灵活的一根旋钮。`[推断，由乘性 gap 直接推出]`

## 4. 汇率从哪来：预生成分期序列

| 问题 | 结论 | 证据 |
|---|---|---|
| 谁生成 | **服务端**；客户端只持 `List<int> Rates` | dump.cs:384557 |
| 怎么变 | 按 `RatePeriod` 分期，交易必须带 `PeriodIndex` | 63997、206677 |
| 过期怎么办 | 报价过期 → `rate_out_date` 拒单 | 10785 |
| 有未来值吗 | 有：`CheatCurrencyExchangeFutureRatesMessage(periodIndex)` | 206606/206618 |
| 有几条曲线 | **单条 `Rates`**，买/卖由 `GetExchangePrice(rate, isBuying)` 派生两条 | 384557/384700 |
| 图表怎么画 | 不插值、不拟合，**直接从 `Rates` 重采样** | 385427/385439 |

### 4.1 图表坐标（可直接抄的 UI 参数）

| 图 | Y 上限 | Y 分段 | Y 每格 | X 每格 | X 标签间隔 |
|---|---|---|---|---|---|
| 日内图 | `1,600,000` | 6 | 266,666 | 3,600,000 ms = **1h** | 14,400,000 ms = 4h |
| 全时段图 | `1,600,000` | 6 | 266,666 | 14,400,000 ms = **4h** | 86,400,000 ms = 24h |

`[实证] dump.cs:384707-384740 区块`

**两张图的意图不同**：日内图回答"今天几点换最划算"（可执行决策），全时段图回答"这波行情该不该囤"（趋势决策）。**Y 轴刻度完全一致**，保证视觉可比。`[推断]`

### 4.2 为什么"预生成"很重要（商业化含义）

- 运营可以**提前编排行情**：活动前拉高 B-Coin 价 → 活动期放量；
- 可以做"预告式经济事件"（玩家只能看到历史与当前，看不到未来——除非作弊通道）；
- 汇率波动是**可控的促销工具**，不是随机噪声。

`[推断，依据 FutureRates 通道 + PeriodIndex 寻址]`

## 5. 额度：`ExpiringResource` 原语

| 字段 | 含义 |
|---|---|
| `BeginTs` | 窗口起点 |
| `PeriodDuration` | 一个周期多长 |
| `Count` | 每周期可用次数/额度 |
| `Cooldown` | 用完后冷却 |

派生：`GetPeriodIndex(ts)` / `GetPeriodStartTs(periodIndex)`。`[实证] dump.cs:64102-64146`

兑换侧落地为 `CurrencyExchangeExpiringResourceData { SellCryptoTs, SellCryptoAmount, BuyCryptoTs, BuyCryptoAmount }` —— **服务端下发 (ts, amount)，客户端自算剩余**。`[实证] dump.cs:214942-214948`

**这套原语全游戏通用**（聚落连接资源、射击场等），是"配额系统"的通用解。复刻时值得直接抽象成基础设施。`[实证] ExpiringResourceDescription 被多处引用`

## 7. 脏钱 → 干净钱：洗钱流水线

### 7.1 公式骨架（字段名即语义）

```
perTick      = CalcDirtyCashPerTick(dirtyByPeriodBase, bonusPercent)
bonusPercent = GetTotalModifierPercent(model, bonuses, now)   // VIP/帮派/区档/模块
             + GetBonusByDirtyAmount(dirtyAmount)             // 体量加成
dirty(t+n)   = max(0, dirty(t) − n×perTick)
clean(t+n)   = min(clean(t) + n×perTick×dirtyToCleanCashModifier, 2147483647)
```

`[实证] dump.cs:172643-172685、85496/85493`

**四条加成来源（与文案一一对应）**：
| 加成 | 文案 key | 来源 |
|---|---|---|
| 体量 | `laundering_by_amount_bonus_title = "bonus based on volume"` | 投入脏钱总量分档 |
| 模块 | `laundering_by_modules_bonus = "Modules"` | 洗钱台升级件 |
| 控制 | `laundering_by_protect_bonus = "Control"` | 区域/区档 |
| VIP | `MoneyWorkbenchLaunderingBonuses.VipEndTs` | 付费 VIP |

`[实证] loc + dump.cs:172730/172802/7872/80027`

### 7.2 洗钱台（MoneyWorkbench）

| 项 | 值/字段 |
|---|---|
| 3 个等级 | `MoneyWorkbench1/2/3` |
| 每级 | `MaxDirtyCashAmount` / `SpeedupUpgradesCount` / `AnalyticsSource` |
| 3 个加速件 | `Speedup0/1/2`，各带 `DirtyCashPerPeriodModifier` |
| 基础参数 | `DirtyCashPerPeriodBase / Period / DirtyToCleanCashModifier` |

`[实证] dump.cs:85463-85467、31864-31868、85501-85503`

### 7.3 两条洗钱路线（付费买便利）

| 路线 | 抽成 | 证据 |
|---|---|---|
| **第三方（Lenny）** | **抽成**："Lenny takes a cut for arranging money laundering." | `loc:laundering_trader_info_description` |
| **自建洗钱台** | 不抽成，但要买台子 + 升级件 + 承担被抢风险 | 设施/升级字段 |

→ **"付费买的是不被抽成"**，比"付费买速度"更高级：它把付费变成"所有权"。`[推断]`

### 7.4 风险与干扰

| 机制 | 作用 |
|---|---|
| `GetLaunderingCablePenalty` / `CutLaunderingCable` / `RepairLaunderingCable` | **洗钱线缆可被剪**（PvP 干扰） |
| `MaxDirtyCashAmount` | 容量上限（超了洗不完） |
| 大便堆事件（历史 T07/T08 已证） | 羞辱性标记 |

## 10. 设计读法（6 条）

1. **把"兑换"藏进银行**，而不是做成"交易所"——降低投机感、提高世界观一致性。
2. **双延迟 = 两类风控**，这是本作最值得抄的一个参数设计。
3. **gap 是乘性抽水**，改一个浮点数就能调全服兑换成本。
4. **汇率预生成** → 运营可以编排行情，把"经济事件"变成促销工具。
5. **洗钱的两条路线（抽成 vs 自建）** 是"付费买所有权"的范式。
6. **取现步长 25,000** 这种"粗粒度"设计，本身就是反精确套利的手段——复刻时别为了"体验顺滑"改成任意金额。
