**矩阵读法**：
- **只有 #1 产生收入**，其余 8 个都是"把收入换成留存/时长/话题"。
- **B-Coin 被设计了 4 个出口**（#2/#4/#5/#6），确保充值后有地方花。
- **#7/#8/#9 不收 B-Coin**，避免"什么都能氪"的 P2W 观感。

## 2. 三条闭环

### 2.1 收入闭环（真钱 → 内容）

```
真钱 → B-Coin（6 档） → 皮肤/战令/单格 → 外观与进度
```
- 特征：**单向、不可逆**（外观不可回售；战令不可退）
- 风险控制：`skin_center_cosmetic_tooltip_description` 明文"不发任何游戏内物品" → 不进入经济
`[实证] loc；[推断] 单向`

### 2.2 现金闭环（时间/风险 → 现金 → 赌场 → 现金）

```
抢劫/卖货 → Cash →（1:1）筹码 → 轮盘 → 筹码 → Cash
```
- 特征：**零和再分配 + 抽水**
- 作用：把"抢来的钱"从"必须洗白"的路径里分出一支，变成"博一把"的路径
- 合规设计：**无真钱入口**，筹码是道具、占背包
`[实证] dump.cs:325629/357420；[推断] 作用`

### 2.3 点数闭环（行为 → 点数 → 页解锁 → 更深页）

```
行为 → BP 点数（上限 MaxPoints）→ 花掉 → 已花费 = 进度 → 解锁更深页 → 更多奖励
                                   └→ 可重复随机池（无限次）
```
- 特征：**消费即进度**（非经验条）
- 作用：把"留存"与"消费"绑成一件事；换州清零防止跨季囤积
`[实证] M04 §2.7；[推断] 作用`

## 3. 付费漏斗与"差一点点"设计

### 3.1 漏斗

| 层 | 设计 | 证据 |
|---|---|---|
| 曝光 | 主菜单轮播（≤5 包）+ 皮肤中心 12 页签 + 战令横幅 | M03 §3 |
| 兴趣 | featured 位 + 30 分钟紧急变色 + 独立计时器 | M03 §3.3 |
| 首购 | 6 档最低 $4.99；外观单件低价引流（面具/背包/武器皮） | M05 §2 |
| 复购 | 战令 Premium → 单格直购 → Premium+ | M04 §3 |
| 追平 | Premium+ 按已领进度折价 | M04 §2.8 |
| 保值 | 重复购买折 B-Coin 补偿 | M03 §6 |

### 3.2 "差一点点"三连（本作转化率的核心）

1. **钱不够** → `BuyCoinsNotEnough(needCryptoCoins)` → `TryGetCoinsPack` **自动选最小够用档**（M05 §6）
2. **点数不够** → 单格直购（B-Coin）立刻到手（M04 §3）
3. **差最后一格集齐** → Main Reward 集齐制（M04 §2.4）

`[实证] 机制；[推断] 这是刻意的转化设计`

### 3.3 付费深度 vs 宽度

| 维度 | 本作做法 | 结果 |
|---|---|---|
| 宽度 | 34 包 + 12 页签 + 6 档 + 172 节点 | 极宽（总有东西可买） |
| 深度 | 单包最贵 $49.99；无"无限充值阶梯" | 中等（不做鲸鱼定向收割） |
| 结论 | **靠"数量 × 频次"而非"单价"** `[推断]` | 适合中 R 主导的长线 |

## 5. 稀缺性矩阵（四种稀缺，各管一层）

| 稀缺类型 | 载体 | 例子 | 作用 |
|---|---|---|---|
| **时间稀缺** | featured / 轮换 / 独立计时器 | `Featured Offer`、`Purchase Time Expired` | 制造"现在买" |
| **资格稀缺** | 区档 / 刑期 / 前置节点 | `Live in a lvl {0} settlement or higher`、`Required jail time ⓤ{0}` | 制造"身份" |
| **数量稀缺** | 聚落数 / 地块数 / 建造槽 | `SectorSettlementsCount`、`MaxSpotsCount`、32 槽 | 制造"抢" |
| **身份稀缺** | 区主/州长/聚落主 | 影子州长、`OwnedSettlementConfig.MaxCount` | 制造"阶层" |

`[实证] 各字段/文案；[推断] 归类`

> **本作最独特的一点**：它把"稀缺"主要放在**资格与身份**（区档/刑期/产权），而不是"抽卡概率"。这是"社会型商业化"而非"赌徒型商业化"。

## 6. 与据点经济的耦合（商业化不能脱离据点）

| 耦合点 | 方向 | 说明 |
|---|---|---|
| 加密矿机 | 据点 → B-Coin | 唯一"免费硬币"阀门；受 32 建造槽/显卡/散热限制（当前未完成） |
| 洗钱台 | 据点 → Credits | 决定玩家能否参与兑换/黑市 |
| 建造/升级件 | 据点 ← 物品 | 130+ SKU 的消耗出口 |
| 聚落公共建筑 | 聚落主 → 居民 | 二级商业化（折扣/加速/防御） |
| 产权凭证 | 解锁树 → 物品价 | **双重门槛**：先解锁资格，再交物品 |

`[实证] M02；[推断] "商业化的地基在据点"`

**结论**：本作的商业化**不是挂在菜单上的商店**，而是**长在据点上的经济**。只抄商店 = 抄了壳；抄据点槽位/升级/矿机/税，才是抄了骨架。`[推断]`

## 9. 关键数值缺口对设计判断的影响

| 缺口 | 若缺失，哪些结论会变 | 影响程度 |
|---|---|---|
| 15 条据点价格表 | 无法判断"买地成本 vs 产出回本周期" | **高** |
| 34 包 B-Coin 价 | 无法判断"外观价格带"与"战令性价比" | **高** |
| Premium / Premium+ 价 | 无法判断战令 ARPPU | **高** |
| 汇率与兑换额度 | 无法判断"白嫖 B-Coin"的效率 | 中 |
| 矿机产出 | 无法判断"免费硬币"是否冲击付费 | 中 |
| 轮盘赔率 | 无法判断抽水与现金回收强度 | 中 |

→ **建议按此顺序抓包/反汇编**（详见 M10）。其中"15 条价格表 + 34 包价 + 战令价"三项拿到后，本套文档即可升级为**可直接排期的数值表**。

## 10. 一句话总结

> **ROB RUN 的商业化不是"卖东西"，而是"设计一套让玩家愿意留在据点里、并把风险与时间换成货币的社会系统"**：真钱买 B-Coin，B-Coin 买身份与外观，时间与风险换成现金与产权，而所有价格都用物品和等级来锚定。
