# M05 · B-Coin 储值包与真实货币通道

> **一句话**：本作的真钱通道不是"Steam 内购"，而是**自建订单网关（steam-ops）+ Steam 只做收银台**；SKU 是 **Pack（给什么）→ Tier（多少钱）→ Transaction（绑定）** 三层，价格点直接写进档位名：`Tier499/999/1499/1999/2999/4999`。
> **证据**：E04（82 KB 证据文件）+ 本文复核的 dump.cs 行号。

---

## 0. 一页结论（9 条）

1. **6 个储值档**：`CryptoCoinsPack0..5` ↔ `Tier499/999/1499/1999/2999/4999` ↔ `TransactionDescriptions.CryptoCoinsPack0..5`，**一一对应**。`[实证] dump.cs:22574-22633、28200-28224、28137-28152`
2. **档位名就是价格点**：499/999/1499/1999/2999/4999 → `$4.99/$9.99/$14.99/$19.99/$29.99/$49.99`。这是**命名推断**，真值在 `SteamPriceAmounts` 字典（服务端/描述二进制）。`[推断+实证] dump.cs:74319`
3. **每档三段促销**：`BaseCryptoCoinsCount` + `BonusCryptoCoinsCount` + `Discount(float)`；`CryptoCoinsCount` 是前两者之和的计算属性。`[实证] dump.cs:63918-63955`
4. **支付通道 = 自建网关**：`api/store-info` / `api/orders` / `api/orders/{0}/action/authorize` / `finalize` / `confirm delivery`，鉴权头 `X-Steam-Auth-Ticket`；Steam 只负责**覆盖层授权回调**（`MicroTxnAuthorizationResponse_t`）。`[实证] dump.cs:424932-424958、425022；lit:*`
5. **多平台收据端点已就绪**：`receipt/steam`、`receipt/google_play`、`receipt/apple_app_store_jws`、`receipt/samsung`、`receipt/test` —— **PC/Steam 先上线，移动端收款能力已备但 UI 未接**（非 Steam 平台走 `EmptyPaymentsProcessor` → Failed）。`[实证] dump.cs:1823271-1823709、445151`
6. **七态订单状态机**：`WaitingPlayer → PlayerAuthorized → Authorizing → WaitingDelivery → Delivered → DeliveryConfirmed → Finished`。`[实证] dump.cs:445463-445469`
7. **"已送达"与"已确认"分开**：服务端推 `Delivered`，玩家点"知道了"才 `DeliveryConfirmed` → 支持**跨设备补弹窗**（`_viewedOrderIds` 本机只弹一次）。`[实证] dump.cs:445604-445632`
8. **余额不足会自动跳档**：`BuyCoinsNotEnough(needCryptoCoins)` → `TryGetCoinsPack` **自动挑一个够用的档**并进入购买流程（战令/商店内直接拉起）。`[实证] dump.cs:448552-448558；ProcessingKey.NotEnoughCryptoCoinsPurchase=1(442371)`
9. **`CurrencyValidator` / `CurrencyAccrualService` 是第三方分析 SDK（DevToDev）的组件，不是本作风控**。这是最容易误判的一处，必须纠正。`[实证] 命名空间 `DevToDev.Core.Internal.*`（dump.cs:1504090/1497280/1510220）`

## 1. 三层 SKU 结构

| 层 | 类 | 字段 | 作用 |
|---|---|---|---|
| **Pack（内容）** | `CryptoCoinsPackDescription` | `CryptoCoinsCount`(=Base+Bonus)、`BaseCryptoCoinsCount`、`BonusCryptoCoinsCount`、`Discount(float)` | 决定"买到多少币" |
| Pack 枚举 | `CryptoCoinsPackDescriptions` | `Pack0..Pack5`（6 档） | 商品清单 |
| **Tier（价格）** | `TransactionTierDescription` | `SteamProductId(int)`、`SteamPriceAmounts(Dictionary<SteamCurrencyDescription,int>)`、`SteamDescriptions(Dictionary<SteamLanguageDescription,string>)` | 决定"多少钱、什么币种、怎么显示" |
| Tier 枚举 | `TransactionTierDescriptions` | `Tier499 / Tier999 / Tier1499 / Tier1999 / Tier2999 / Tier4999` | 价格点 |
| **Transaction（绑定）** | `TransactionDescription` | `Tier(Func)`、`CryptoCoinsPack(Func)`、`ShopPack(Func)`、`SteamDescriptions` | 把"内容"与"价格"绑成可售 SKU |
| Transaction 枚举 | `TransactionDescriptions` | `CryptoCoinsPack0..5` | 上架 SKU |

`[实证] dump.cs:63918-63955（Pack）、74315-74322（Tier）、74257-74267（Transaction）、22574/28200/28137（三个枚举）`

**关键设计**：`TransactionDescription` 同时能指向 `CryptoCoinsPack` **或** `ShopPack` → **同一套订单/支付/发货管线既卖币也卖皮肤包**。这是它能"一个网关卖所有东西"的原因。`[实证+推断] dump.cs:74261-74267`

## 2. 六档明细（**到账币数已实证**，金额为命名推断）

**先看真值**：Steam 商品展示名（`stringliteral.json`）直接写出了每档的 B-Coin 数：

| Steam 展示名 | → 对应档位 | 到账 B-Coin |
|---|---|---|
| `B-Coin pack: 500` | Pack0 / Tier499 | **500** |
| `B-Coin pack: 1100` | Pack1 / Tier999 | **1,100** |
| `B-Coin pack: 1700` | Pack2 / Tier1499 | **1,700** |
| `B-Coin pack: 2400` | Pack3 / Tier1999 | **2,400** |
| `B-Coin pack: 3700` | Pack4 / Tier2999 | **3,700** |
| `B-Coin pack: 6500` | Pack5 / Tier4999 | **6,500** |

`[实证] stringliteral.json: "B-Coin pack: 500/1100/1700/2400/3700/6500"（6 条）+ E02 §3.4`

| # | Pack | 到账 B-Coin | 赠币 | 折扣 | 绑定 Tier | 单币价（按推断 USD） | 相对首档 |
|---|---|---|---|---|---|---|---|
| 0 | `Pack0` | **500** | ? | ? | `Tier499` | $4.99 → **$0.00998/币** | 100% |
| 1 | `Pack1` | **1,100** | ? | ? | `Tier999` | $9.99 → $0.00908/币 | 91% |
| 2 | `Pack2` | **1,700** | ? | ? | `Tier1499` | $14.99 → $0.00882/币 | 88% |
| 3 | `Pack3` | **2,400** | ? | ? | `Tier1999` | $19.99 → $0.00833/币 | 83% |
| 4 | `Pack4` | **3,700** | ? | ? | `Tier2999` | $29.99 → $0.00810/币 | 81% |
| 5 | `Pack5` | **6,500** | ? | ? | `Tier4999` | $49.99 → $0.00769/币 | 77% |

`[实证] 币数（展示名）；[实证] 档位结构；[推断] USD 金额（由档位命名 499→$4.99 得出，未读到 SteamPriceAmounts）`

> **单币价从 $0.00998 一路降到 $0.00769（−23%）**，是标准的"越大越划算"阶梯；但**降幅温和**（没有出现常见的 −50% 大包），说明它更依赖"赠币 + 折扣"而非"单价跳水"来做大 R。`[推断]`

**两个"没有"（同样重要）**：
- **没有限购/限时/首充字段**：`CryptoCoinsPackDescription` 只有 4 个字段（`CryptoCoinsCount / Base / Bonus / Discount`），**没有** `Limit / StartTs / EndTs / FirstPurchase`；而同一套管线上的 ShopPack **有** `AvailabilityStartTs/EndTs/IsPermanent/IsHidden`。→ **储值是"常青货架"，皮肤是"稀缺货架"**。`[实证] dump.cs:63918-63955 vs 75880-75903`
- **客户端只支持 USD / RUB 两种币种**：`SteamPriceAmounts: Dictionary<SteamCurrencyDescription,int>`，枚举侧只落这两个。`[实证] E05 §1 + dump.cs:74319`

**为什么价格写进 id**：① 运营/客服一眼可读 ② 防配置错位 ③ A/B 时新增档位不用改代码（加一个 `Tier7999` 即可）。这是**廉价但有效**的工程化做法，复刻可直接抄。`[推断]`

## 3. 三段促销结构（UI 同时展示三段信息）

`CryptoCoinsPackViewDescriptions.BuyOfferPackDescription` 的类型是 `Text.ReadOnly<Money, Money, string>` —— **两个 Money + 一个 string**，正好对应"原价 → 折后价 → 币数"三段。`[实证] dump.cs:448298`

| 段 | 字段 | 玩家看到 |
|---|---|---|
| 原价 | `Discount` 反推 + `SteamPriceAmounts` | 划线价 |
| 折后价 | `GetPriceText(transaction, currency)` | 实付价 |
| 币数 | `Base + Bonus` | "+{Bonus} BONUS"（`loc:coins_bonus_label = "+ {0:N0} BONUS"`） |

`[实证] loc:coins_bonus_label、loc:buy_offer_pack_title="Buy B-Coins"、loc:buy_offer_pack_buy="Buy {0}"`

> **`Discount` 是独立于赠币的第三根杠杆**：赠币改变"单币价"，折扣改变"实付价"，两者可叠加也可分开做。复刻时若只做赠币，会少一半促销空间。`[推断]`

## 4. 真实货币通道：自建网关 + 平台收银台

### 4.1 端点

| 端点 | 用途 |
|---|---|
| `api/store-info` | 拉商店快照（用户币种 + 可售档位） |
| `api/orders` | 建单 |
| `api/orders/{0}/action/authorize` | 订单授权 |
| （finalize） | 服务端确认收款后发货 |
| `confirm delivery` | 客户端确认收货 |
| `verify/payment` | 支付校验 |
| `login/steam` | Steam 票登录 |
| `receipt/steam` / `receipt/google_play` / `receipt/apple_app_store_jws` / `receipt/samsung` / `receipt/test` | 五类收据 |

`[实证] stringliteral.json（lit:"api/store-info" 等）；基址由配置 `steam_ops_urls` 提供（[未知-配置]）`

### 4.2 鉴权与请求

- 头：`X-Steam-Auth-Ticket`（所有 steam-ops 请求）
- 建单体：`{uid, transaction_tier, virtual_item_id, language, currency}`
- 重试：`SteamOpsApiClient send url={0} attempt={1}/{2}`（带次数）

`[实证] E04 §11 B1/B2`

### 4.3 平台角色（这一点最容易被误解）

```
玩家点 Buy
   → 自建后端建单（有价格、有币种）
   → Steam 覆盖层只做"授权"（MicroTxnAuthorizationResponse_t）
   → 后端 Finalize（真正扣款/发货）
   → 客户端收 Delivered 通知
```

→ **Steam 不是商店，只是授权弹窗**。这意味着：① 价格可服务端随时改（不受 Steam 商店页约束）② 可以做"余额不足自动选档"这种跨 SKU 逻辑 ③ 移动端复用同一后端，只需换收据校验。`[实证+推断]`

### 4.4 移动端：能力已备、UI 未接

| 证据 | 含义 |
|---|---|
| 5 类 `*Receipt` DTO（Steam/GooglePlay/AppleAppStoreJwt/Samsung/Test） | 多平台收据校验已实现 |
| `EmptyPaymentsProcessor` 在非 Steam 平台一律 `Failed` | 当前构建**只发 PC** |
| `AppleAppStoreJwtReceipt` 用 **JWS** 格式 | 适配 2024+ Apple 服务端通知规范 |

`[实证] dump.cs:1823271-1823709、445151`

## 5. 七态订单状态机

| 值 | 状态 | 语义 |
|---|---|---|
| 0 | `WaitingPlayer` | 已建单，等玩家在覆盖层确认 |
| 1 | `PlayerAuthorized` | 玩家已点"授权" |
| 2 | `Authorizing` | 正在向后端确认授权 |
| 3 | `WaitingDelivery` | 已付款，等后端发货（B-Coin 到账） |
| 4 | `Delivered` | 已发货 |
| 5 | `DeliveryConfirmed` | 客户端已确认收货 |
| 6 | `Finished` | 闭环，可清理 |

`[实证] dump.cs:445463-445469`

**状态迁移的落地函数**：
`ApplyPlayerAuthorization(orderId, authorized)`（0→1）、`TryGetConfirmedPurchase`（3→4）、`ConfirmDelivery(orderId)`（4→5）、`RemoveFinishedPurchases()`（5→6 删除）。`[实证] dump.cs:445575/445525/445632/445532`

### 5.1 端到端时序（16 步压缩）

| # | 动作 | 关键符号 |
|---|---|---|
| 1 | 玩家点 Buy | `GetTransaction(pack)` → `TransactionDescription` |
| 2 | 检查 Steam 覆盖层 | `IsOverlayEnabled`；无则弹 `SteamOverlayRequirement*` |
| 3 | 拉商店快照 | `GET api/store-info`（`X-Steam-Auth-Ticket`） |
| 4 | 建单 | `POST api/orders` → `OrderResponse{order_id, transaction_id}` |
| 5 | 落地本地订单 | `PurchaseModel{OrderId, TransactionId, State=WaitingPlayer}` |
| 6 | 授权 | `POST api/orders/{order}/action/authorize` |
| 7 | Steam 覆盖层 | `MicroTxnAuthorizationResponse_t` → 授权/取消 |
| 8 | 回写状态 | `ApplyPlayerAuthorization` → 1 或取消 |
| 9 | 后端确认 | `FinalizeOrder` |
| 10 | 发货 | B-Coin 余额推送（`IPrimitiveData<int>`） |
| 11 | 客户端发现 | `ReadDeliveredTransactions` → `Delivered` |
| 12 | 弹窗 | `payment_purchase_completed_title` / `payment_crypto_coins_purchased_description` |
| 13 | 玩家确认 | `ConfirmDelivery` → `DeliveryConfirmed` |
| 14 | 清理 | `RemoveFinishedPurchases` |
| 15 | 兜底 | `_failedTransactionIds` 防无限重试 |
| 16 | 错误分支 | `Error(Reason) / BannedError / RejectedError / StoreUnavailableError` + `DetailErrorResponse{message, slug}` |

`[实证] E04 §9.2 全表`

### 7.1 客户端（软校验，只影响体验）

|---|---|
| `CanPerformShopActions` | 战斗中/非法场景禁用购买 |
| 覆盖层检测 | 无 Steam Overlay 直接拦 |
| 价格 TTL（`price_out_date`） | 旧价下单被拒 |
| `PurchaseState` 单例保护 | 同单不重复弹窗 |
| `_failedTransactionIds` | 防无限重试风暴 |

`[实证] 上述符号均已定位`

### 7.2 服务端（真风控）

- 幂等键：`orderId is already used`（字符串字面量）
- 订单状态机由服务端推进；客户端只是"跟随"
- `BannedError` / `RejectedError` 由后端返回
- 退款/拒付：**客户端无符号**，只有 `CancelOrder` → 属平台后台/服务端流程 `[未知]`

### 7.3 常见误判纠正

| 误判 | 事实 |
|---|---|
| `CurrencyValidator` = 游戏风控 | 属 **DevToDev** 分析 SDK，做的是"付费事件上报的 ISO 币种白名单 + 去重" |
| `CurrencyAccrualService` = 货币发放服务 | 同上，第三方分析 SDK 的"收入聚合" |

## 8. 设计读法（7 条）

1. **价格点用 99 结尾的 6 档阶梯**：$4.99→$49.99，覆盖"试水/小额/中额/大额"，且**最高档是最低档的 10 倍**——典型的大 R 承接结构。
2. **三段促销（原价/折扣/赠币）** 让同一个包可以做出 4 种活动形态：打折、加赠、既打折又加赠、恢复原价。
3. **档位名写价格** 是运营效率设计：活动期加一档 `Tier7999` 不需要改代码。
4. **自建网关** 换来定价自由 + 跨平台复用 + 可以做"自动补差"这类跨 SKU 逻辑。
5. **Delivered / DeliveryConfirmed 分离** 支撑跨设备补弹窗，减少"我付了钱没收到东西"的客诉。
6. **移动端能力先埋、UI 后接** 是典型的"平台扩展预留"，复刻时应照做（收据校验比 UI 难得多）。
7. **合规红线**：文案 `skin_center_cosmetic_tooltip_description` 明确"不发放任何库存/游戏内物品"——即**付费只买外观**。这条在本作是**写进 UI 的承诺**，不是口头设计。
