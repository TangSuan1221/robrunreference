# M07 · 非商店售卖面：赌场轮盘 / 无限奖励 / 黑市解锁树

> **一句话**：除了商店和战令，本作还有三条"卖东西"的路，但它们**各自锚定不同货币**：轮盘锚 **现金**、无限奖励锚 **战令点数**、黑市解锁树锚 **Credits**。把它们混成一个"商业化系统"会完全误判经济。
> **证据**：E05（838 行）+ 本文复核。

---

## 0. 一页结论（9 条）

1. **四条售卖面货币互不通用**：储值包卖 B-Coin；轮盘只收 **Cash→筹码**（**无真钱入口**）；无限奖励收 **BP 点数**；黑市解锁树收 **Credits + 实物 + 刑期 + 区级 + 前置节点**。`[实证] E05 §1`
2. **轮盘是"现金回收池"，不是付费面**：筹码是**物理道具**（占背包格）、用**实体现金**买卖、1:1 面值。它把"抢来的现金"回收成"赢来的筹码"，再变回现金——**没有付费入口，规避博彩合规风险**。`[实证] dump.cs:325629/357420/204208`
3. **轮盘是欧式单零 37 格**（0–36，无 00），**157 个下注位**、12 种注型、5 种筹码面额（1k/5k/25k/50k/100k）。`[实证] dump.cs:78055/30064-30309/30364`
4. **抽水只能推不能读**：37 格 + 标准欧式赔率 → RTP = 36/37 = **97.30%**，庄家 2.70%；但真实 `Odds` 12 个整数在 `.cctor`，**客户端拿不到**，且 `MaxRewardAmount` 会截断大奖 → 真实抽水 `[未知]`。`[实证+推断-数学]`
5. **无限奖励不是新系统，是战令的"可重复随机行"**：`Price` 是 **BP 点数**、**没有 `CryptoCoinsPrice`**（不能真钱买）、奖池完全隐藏、**客户端无任何保底/计数/衰减字段**。`[实证] dump.cs:129901-129931 + E05 §5`
6. **黑市解锁树 = 172 节点 / 3 页签 × 4 商品层级**：`Construction / Gear / Vehicles` × `BASIC → LEVEL1 → LEVEL2 → LEVEL3`，每家族内部还有 2–3 个 Mark。`[实证] dump.cs:25589-26116 + loc:laptop_tab_* / laptopb_tier_*`
7. **解锁是 5 维门槛 + 1 开关**：`CoinsPrice` / `ItemsPrice` / `RequiredImprisonmentYears` / `RequiredTier` / `RequiredNodes` / `IsEnabled`。**"刑期"被当成江湖地位门槛**——这是本作最有辨识度的一处。`[实证] dump.cs:71279-71339`
8. **解锁货币是 Credits 不是 B-Coin**：`VendorTreeNodeParams.CoinsPrice` + `vendor_tree_unlock_with_coins_button` + `not_enough_coins="Not enough credits"`，四重证据。`[实证]`
9. **解锁价格在服务端**：存在专门的服务端计数消息 `GetLockedVendorTreeNodesPriceItemsCountMessage`（还带限频），证明"总价由服务端算"。`[实证] dump.cs:203120；[推断] 单价在服务端`

## 1. 四条售卖面的货币隔离（先看这张表）

| 售卖面 | 收什么 | 卖什么 | 真钱入口 | 影响经济平衡 |
|---|---|---|---|---|
| B-Coin 储值包 | 真实货币（USD/RUB） | B-Coin | ✅（唯一） | 单向注入 |
| 皮肤商店 | B-Coin | 34 个外观包 | ❌ | 无（纯外观） |
| 战令 | B-Coin + BP 点数 | 外观轨 + 随机池 | ❌（用 B-Coin） | 弱 |
| **轮盘** | **Cash** | 筹码/派彩 | **❌** | **强（现金再分配）** |
| **无限奖励** | **BP 点数** | 随机物品 | ❌ | 弱 |
| **黑市解锁树** | **Credits + 实物 + 刑期 + 区级** | 商品目录解锁 | ❌ | **中（产能闸门）** |

`[实证] E05 §1；货币定义见 M06 §1`

> **结论**：真正能"改变经济"的只有 **B-Coin 注入（真钱）** 与 **轮盘（现金再分配）**。商店/战令/解锁树都只是"把已有资源换成内容"。

### 2.2 筹码：5 面额 / 物理道具 / 现金 1:1

| 项 | 内容 |
|---|---|
| 面额 | `Chip1k / Chip5k / Chip25k / Chip50k / Chip100k` |
| 形态 | 每种筹码绑定一个**背包道具**（`RouletteChipDescription.ItemFunc`） |
| 背包摩擦 | 交易/领奖前要**先找格子**；装不下奖励退回（`TryFindInventorySlotsForChip` / `AddChipsToInventory(..., out restReward)` / `HasSpaceForAnyReward`） |
| 道具 id | `chip_1k / chip_5k / chip_25k / chip_50k / chip_100k` |
| 买卖配方 | `roulette_chip_{1,5,25,50,100}` × 5 面额 = **25 条批量配方** |
| 用什么买 | **Cash（实体现金）**，不是 Credits、不是 B-Coin |
| 兑换率 | 消息体**无价格字段**（只有面额/数量/方向）→ **1:1 面值**（强推断） |
| 锁定态 | `RouletteRecipeView.LockState { Unlocked, LockedToBuy, LockedToSell }` |

`[实证] dump.cs:30364-30393、78020-78047、325629、357420、204208-204245、9891-9915`

**设计读法**：筹码道具化 + 占背包 + 1:1 现金 → ① 不能真钱赌，合规安全 ② 赢多了装不下，强制反复兑换往返，形成**现金回收的物理减速带**。`[推断]`

### 2.4 赔率与抽水：只能推，不能读

| 层 | 结论 |
|---|---|
| 几何 | 37 格等概率 → `P(单号)=1/37` `[实证]` |
| 标准欧式 RTP | `RTP = Odds × 覆盖数/37`；若 `Odds[Straight]=36` → **36/37 = 97.30%**，庄家 **2.70%** `[推断-数学]` |
| 恒等式 | `Odds × 覆盖数 = 36` 对所有标准注型成立 → 不做优待注型时抽水恒为 1/37 |
| 真实抽水 | **`[未知]`**：`RouletteBetOddsConfig.Odds : Dictionary<RouletteBetType,int>` 的 12 个整数在 `.cctor`；`MaxRewardAmount` 会截断大奖 → 实际 RTP 可能更低 |

`[实证] dump.cs:77999-78016、159688-159705、9900-9903；[推断-数学] 公式`

> **给策划的提醒**：`Odds` 的整数语义（"总返还倍数"vs"净赢倍数"）不可辨。若 `Odds[Straight]=35`（净赢 35 + 退本金），RTP 仍是 36/37；若 `=34`，则是暗抽水。**必须反汇编或实测**。

## 6. 设计读法（7 条）

1. **每个面只锚一种货币**：轮盘=现金、无限奖励=点数、解锁树=Credits、商店=B-Coin。**互不串味**是这套经济清晰的前提。
2. **轮盘是"回收"不是"售卖"**：它把玩家抢来的现金重新分配，并制造全服广播话题。**没有真钱入口**是合规底线。
3. **解锁树把"内容"变成"目标"**：172 个节点 = 172 个中期目标，且用刑期/区级/前置做成"身份门槛"。
4. **"买地资格也在树里"**：说明产权不是"有钱就能买"，而是"先证明你是这个圈子的人"。这是**社会性付费门槛**。
5. **无限奖励没有保底、没有付费入口**：它是留存工具，不是抽卡变现。
6. **服务端权威贯彻到底**：连"剩余材料总数"都要问服务端（还限频）。
7. **抽水无法从客户端读出**：这不是逆向失败，而是设计上的"经济参数不外泄"。
