## 0. 一页结论（10 条）

1. **据点是本作唯一的"产能底座"**：没有地块 → 不能建造 → 没有工作台/矿机 → 没有产出 → 商业化资源只能靠买。
2. **据点的价格不是钱，是物品**：`TierParams` 挂 5 张 `InventoryItemsPrice` × 3 个区档 = **15 条价格条目**（`tier_1_plot_price` … `tier_3_local_move_plot_price`）。`[实证] dump.cs:80043-80051、strings_game.txt:1064-1081`
3. **区档（Tier1/2/3）不是难度，是"一整套经济参数包"**：16 个字段同时改物价、税率、洗钱速率、帮战门槛、聚落数量、能否买聚落。`[实证] dump.cs:80017-80079`
4. **每个区还有自己的"收购价修正"**：`SectorParams.BuyerSectorModifier`（float）——同一件货在不同区卖价不同，这是**地缘价差**的代码依据。`[实证] dump.cs:79819`
5. **建造槽是封闭的 32 种**，建筑目录也是封闭的（主屋 3 / 附属 9 / 围墙 4）。**付费深度 = 这 32 个槽里能塞多少"升级件"**，不是槽本身能卖钱。`[实证+既有文档] dump.cs:126820`
6. **7 类生产设施 = 7 条独立的"时间→资源"曲线**，每台都有自己的槽位/节拍/三条升级线（速度 / 容量 / 效率）。这是本作最值得抄的"非数值付费"结构。`[实证] 详见 T07`
7. **加密矿机是唯一产出"付费货币"的设施**：显卡槽（Power/ResourcePoints）× 散热槽（降消耗）× 加速槽（提速率），产物是 `OutputItem`（钱包类物品）。**当前构建只有 1 台/1 卡/1 散热/1 加速，且文案标注 `in development`**。`[实证] dump.cs:43865-44044、loc:building_bonus_crypto`
8. **聚落主是"二级平台"**：能买 8 种公共建筑（加密货币/实验室/农场/武器折扣/装备折扣/防御点/封锁站/酒类贸易），给居民发 7 类加成，并向居民**抽税**。`[实证] dump.cs:29744-29818、76866-76875`
9. **据点的"商业化资源"其实有 4 类**：① 建造/升级件（物品）② 加密矿机三件套（显卡/散热/加速）③ 产出物（货物/收集品/硬币）④ 产权凭证（Land Plot Title / Settlement Title / Bill of Sale）。四类的获取与定价机制**完全不同**。
10. **付费深度测算**：单地块的理论付费点 ≈ **32 建造槽 × 平均 2.5 条升级线 ≈ 60-80 个"可付费升级位"**；其中只有矿机三槽直接影响硬币产出，其余影响"效率"。**本作刻意让 90% 的付费点只买效率、不买产出上限**。

### 4.3 升级件的"三线互斥"设计（最值得抄的一条）

每台设施的升级槽分三类，**各占独立槽位、不能互相替代**：

| 线 | 效果字段 | 代表件 | 玩家取舍 |
|---|---|---|---|
| **速度** | `SpeedupPercent` / `SpeedupModifier` / `DirtyCashPerPeriodModifier` | 工具箱、圆锯、等离子切割机、点钞机 | "我要更快" |
| **容量** | `AdditionalSlots` | 夹钳、称重器、工具箱（扩容） | "我要并行更多" |
| **效率/结构** | `ResourceDecreaseModifier` / 权重表 | 散热器、引擎、温度计、转换器 | "我要更省/更好产出" |

`[实证] dump.cs:101404-101473（矿机两线）、既有 T07 §4`

→ **付费深度不来自"等级"，来自"三条线只能选一条"的稀缺性**。这是把"数值付费"转成"配置付费"的关键手法。

## 6. 专题：加密矿机（唯一"时间→付费货币"阀门）

### 6.1 结构

```
CryptoWorkbenchDescription.Workbench1
  ├─ VideoCardSlotsCount   → 插显卡（VideoCardDescription）
  ├─ CoolingSlotsCount     → 插散热（CryptoWorkbenchEfficiencyUpgradeDescription）
  └─ SpeedupSlotsCount     → 插加速（CryptoWorkbenchSpeedupUpgradeDescription）
CryptoWorkbenchConfig.Default
  ├─ OutputItemFunc / OutputItem     → 产物（"钱包类"物品）
  ├─ OutputItemStackSize             → 单次堆叠
  └─ BrokenCardFunc / BrokenCard     → 显卡会"坏"（损坏态物品）
```

`[实证] dump.cs:101283-101400、43822-43885`

### 6.2 两条数值线（显卡）

| 字段 | 语义 | 作用 |
|---|---|---|
| `VideoCardDescription.Power` | 算力 | 决定产出速率（分子） |
| `VideoCardDescription.ResourcePoints` | 资源消耗点 | 决定消耗（分母），散热件降低它 |
| `VideoCardDescription.IsBroken` | 是否损坏 | 坏卡不能算 |

`[实证] dump.cs:101671-101710`

**产出模型（`[推断]`，依据字段名与两条升级线）**：

```
产出速率 ≈ Σ(GPU.Power) × (1 + Σ SpeedupModifier) / (Σ GPU.ResourcePoints × (1 - Σ ResourceDecreaseModifier))
```

**当前内容量**：`CryptoWorkbenchDescriptions` 只有 `Workbench1`（1 台）；`VideoCardDescriptions` 只有 `Card1` + `BrokenCard`（1 张 + 坏卡）；`CryptoWorkbenchEfficiencyUpgradeDescriptions` 只有 `Cooling1`；`CryptoWorkbenchSpeedupUpgradeDescriptions` 只有 `SpeedupUpgrade1`。
`[实证] dump.cs:43865、44012、43913、43961`

→ **这是一条"框架完整、内容未填"的线**。文案 `building_bonus_crypto = "Increased graphics card performance (in development)"` 直接坐实。`[实证] loc:building_bonus_crypto`

### 6.3 为什么它是商业化的关键

| 设计意图 | 证据 |
|---|---|
| 给白嫖玩家一条"时间换付费货币"的路（否则 B-Coin 只能买） | `StartCryptoCoinsCount = 0` + 矿机产出 |
| 但产出被"槽位数 × 显卡等级"卡死（不能无限堆） | `VideoCardSlotsCount` |
| 且显卡会坏（`BrokenCard`）→ **持续性消耗** | `CryptoWorkbenchConfig.BrokenCard` |
| 散热件降低消耗 → **效率付费** | `ResourceDecreaseModifier` |
| 联邦没收时 B-Coin 不受影响 → **矿机资产是"安全资产"** | `loc:tsd_u_civil_banker_npc_b_4` |

**结论**：矿机=本作的"金币矿"，但它被设计成**低效、易损、有上限**，以确保付费仍是主要来源。这是"免费货币不能冲击付费"的教科书式解法。

**设计读法**：聚落主花物品买建筑 → 建筑给居民加成 → 聚落更吸引人 → 地租/税收更高。**这是"玩家自治的 SaaS"**：聚落主是房东 + 平台运营者。复刻时这条线最容易漏。
