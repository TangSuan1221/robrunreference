## 0. 一页结论

1. ROB RUN 的"局外空间"是 **6 层嵌套容器**，每层都有独立的**标识枚举**（`Region` 字符串 → `RealmId` → `SectorDescription` → `SettlementDescription` → `Plot` → `PlotBuilderSlotTypeDescription`）。
2. **配置与数据彻底分离**：
   - **配置**（"世界长什么样"）= `Models.References.*`，`[BinarySerializable]`，由 `StaticReferences.Build(environment)` 从服务器下发的 `.bytes` 反序列化；
   - **数据**（"现在归谁、建了什么"）= `Models.Data.*`，双份：`Database*Data`（服务端权威）+ `BuildClient()` 出来的客户端副本，经 `Models.Replication.*` 同步。
3. **空间选择是"三层选择"**：`Region`（延迟）→ `Realm/State`（人口与寿命）→ `Sector`（区，帮派产权）→ `Settlement`（聚落，个人/系统产权）→ `Plot`（家）。
4. **每层都有自己的"数量上限字段"**，这些字段就是整个政治结构的参数化来源（`TierParams.SectorSettlementsCount`、`OwnedSettlementConfig.MaxCount`、`PlotSpotConfig.MaxSpotsCount`…）。
5. 本地**拿不到任何价格/税率/寿命的具体数值**：这些全在 `references .bytes` 里。**但 schema 是完整的**，本文件把每一层的字段都列全了，因此抓包后可 1:1 填表。

## 2. 权威流：配置层 / 数据层 / 实体层

### 2.2 复制通道：`IPrimitiveData<T>` 家族

```csharp
// 命名空间 Models.Data / Models.Replication
IPrimitiveData<T>   // 可同步、可脏标记的标量
BoolData : IPrimitiveData<bool>
IntData  : IPrimitiveData<int>

```

`[实证]`（类型存在 + 用于所有数据类字段）

**设计含义**：`DictionaryData` 说明"加一个储物箱"是**增量同步**，不是整包重传；`TimestampData` 说明"突袭锁到期"是**本地按时间戳判定**，不需要服务端逐秒推送。`[推断]`

### 2.3 配置下发：为什么本地一个数字都没有

证据链（与既有《基地建造-逆向分析》§7.5 一致，本文件补充结构层结论）：

1. 所有配置类都带 `[BinarySerializable]` 与成对 `*BinarySerializer`（`IBinaryReadStream` / `ReadOnlyEnum<T>` / `Lazy`）`[实证]`
2. 字符串字面量里有 `references-provider`、`references_hash`、`RemoteReferencesProvider inner`、`LoadingFailedReferencesError`、`DecodeFailedReferencesError`、`Settlement.bytes`、`/config.json` `[实证]`
3. 359 个 bundle 里**没有**任何配置型 ScriptableObject（只有 View Description）`[实证]`

**→ 数值获取路径（按成本排序）**：
- **A. 抓包**：`RemoteReferencesProvider` 走 HTTPS + hash 校验；解密后用 `*BinarySerializer` 的字段顺序写解析器（本系列文档就是这套 schema）。
- **B. 进程内存**：references 加载后已在托管堆；用 `CodeRegistration/MetadataRegistration` 定位。
- **C. 静态反汇编**：按 RVA 反汇编 `StaticReferences.Build` 读内联常量（最费力）。
