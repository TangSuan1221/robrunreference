## 0. 一页结论

1. **6 类工作台 + 1 个采集台**，全部是"**槽位 + 计时器 + 升级位**"三件套；没有"生产队列"，只有"tick 驱动"。
2. **升级分两种正交维度**：
   - **速度升级（Speedup）** → `SpeedupPercent` / `SpeedupModifier` / `DirtyCashPerPeriodModifier`
   - **容量升级（AdditionalSlot）** → `AdditionalSlots`
   两者**不能互相替代**，且各自占独立槽位。
3. **加密矿机是唯一有"资源消耗"的设施**：`CryptoWorkbenchEfficiencyUpgradeDescription.ResourceDecreaseModifier` —— 它不是纯增益，而是**降低消耗**。
4. **每类工作台都有 `SpawnLootPoint`**：产出/掉落统一落在工作台外的指定点（与 T06 的"掉落点在门外"同构）。
5. **采集台（CollectionTable）是唯一的"奖励型"设施**：它不出售、不产出货币，而是**产出收集品**（`RewardPosition` / `RewardInteractPoint` / `LootSpawnPoint`）。

## 2. 逐台解剖

### 2.1 开箱台（`CargoOpenWorkbenchDescription`）

```csharp
public class CargoOpenWorkbenchDescription : MyEnumItem {
    CollidersDescription Colliders;
    IReadOnlyList<OBB> Obbs;
    Func<InventoryItemDescription> InventoryItemFunc;      // 建造这台需要的物品
    Vector3 InteractPoint;
    InteractDescription InteractDescription;
    Vector3 SpawnLootPoint;                                // 开完箱，东西掉这
    int SlotsCount;                                        // 基础槽数
    CargoWorkbenchTypeDescription WorkbenchType;           // 台型（普通/实验室…）
    IReadOnlyList<CargoOpenWorkbenchAdditionalSlotUpgradeDescription> AdditionalSlotUpgrades;
    IReadOnlyList<CargoOpenWorkbenchSpeedupUpgradeSlotDescription> AvailableSpeedupUpgradeSlots;
}
```

**两种升级的定义**（`[实证]`）：

```csharp
// 加槽位（容量）
public class CargoOpenWorkbenchAdditionalSlotUpgradeDescription : MyEnumItem {
    Func<InventoryItemDescription> ItemFunc;   // 用哪件物品升级
}
// 加速度（按"槽类型"限定）
public class CargoOpenWorkbenchSpeedupUpgradeDescription : MyEnumItem {
    CargoOpenWorkbenchSpeedupUpgradeSlotTypeDescription SlotType;  // 这个加速件能装哪种槽
    float SpeedupPercent;
    Func<InventoryItemDescription> ItemFunc;
}
```

**关键**：**加速件有"槽类型"限制**（`SlotType`）——不是所有加速件都能装所有槽。`[实证]`

### 2.2 贸易台（`CargoExchangeWorkbenchDescription`）

```csharp
public class CargoExchangeWorkbenchDescription : MyEnumItem {
    Func<InventoryItemDescription> InventoryItemFunc;
    int BaseSlotsCount;                    // 基础槽
    int SpeedupUpgradeSlotsCount;          // 可装几个加速件
    int AdditionalSlotUpgradeSlotsCount;   // 可装几个加槽件
    CollidersDescription Colliders;
    Vector3 InteractPoint;
    InteractDescription InteractDescription;
    Vector3 SpawnLootPoint;
    IReadOnlyList<OBB> Obbs;
    CargoWorkbenchTypeDescription WorkbenchType;
}
```

**与开箱台的区别**：贸易台的**升级槽数量是"配置死的"**（`SpeedupUpgradeSlotsCount` / `AdditionalSlotUpgradeSlotsCount`），不是"列表"——说明它的升级是**固定几个位置**，玩家选装什么。`[实证+推断]`

**升级效果**（`[实证]`）：
```csharp
CargoExchangeWorkbenchSpeedupUpgradeDescription : { InventoryItem, float SpeedupPercent }
CargoExchangeWorkbenchAdditionalSlotUpgradeDescription : { InventoryItem, int AdditionalSlots }
```

### 2.3 生产台（`CargoProductionWorkbenchDescription`）—— 唯一有"tick 节奏"的

```csharp
public class CargoProductionWorkbenchDescription : MyEnumItem {
    Func<InventoryItemDescription> InventoryItemFunc;
    Vector3 InputInteractPoint;            // 投料点
    Vector3[] InteractPointSlots;          // 每个槽一个交互点
    Vector3 SpawnLootPoint;
    long ResultTickDuration;               // ← 一个 tick 多长
    int ResultTickCount;                   // ← 产一次要几个 tick
    IReadOnlyList<CargoProductionWorkbenchResultWeightsUpgradeSlotDescription> AvailableResultWeightsUpgradeSlots;
    int ResultCargoSlotsCount;
}
```

**生产节奏公式**（`[实证字段 + 推断]`）：

```
一次产出的时长 = ResultTickDuration × ResultTickCount
产出种类 = 由 ResultWeightsUpgradeSlot 改装后决定（权重表）
产出数量 = 由 ResultCargoSlotsCount 限制
```

**"权重升级"是什么**：`CargoProductionWorkbenchResultWeightsUpgradeDescription` 只有 `Item` + `SlotType`，没有数值——说明**改装件不改数值，只改"权重表的选择"**（例如装"引擎"件 → 产出更偏向某类货物）。`[实证+推断]`

### 2.4 充电/催熟台（`CargoChargeWorkbenchDescription`）

```csharp
public class CargoChargeWorkbenchDescription : MyEnumItem {
    CargoChargeWorkbenchTypeDescription WorkbenchType;   // 花园床/冷冻机/…
    int CargoInventorySlotsCount;
    long TickPeriod;                                     // 每个 tick 周期
    bool CanCollectChargedCargoReward;
    long CollectChargedCargoRewardTime;                  // 收取奖励的时长
    // 升级
    IReadOnlyList<CargoChargeWorkbenchSpeedupUpgradeSlotDescription> AvailableSpeedupUpgradeSlots;
}
```

`[实证]`

**两类台型**（`[实证-本地化]`）：
- `GrowTable`（花园床）→ 种植物
- `IndustrialFreezer`（工业冷冻机 ×3）→ 冻结晶

**`CanCollectChargedCargoReward` 是开关**：开启后，充电完成的货物可以被"收割"并给额外奖励（`building_farm_1_bonus` = "Chance of an additional harvest +{BonusRewardProbability:0%}"）。`[实证+推断]`

### 2.5 加密矿机（`CryptoWorkbenchDescription`）—— 唯一"消耗型"

```csharp
public class CryptoWorkbenchDescription : MyEnumItem {
    int VideoCardSlotsCount;    // 显卡位
    int SpeedupSlotsCount;      // 加速位
    int CoolingSlotsCount;      // 散热位
}
// 升级
public class CryptoWorkbenchEfficiencyUpgradeDescription : MyEnumItem {
    float ResourceDecreaseModifier;   // ← 降低资源消耗（不是加产出）
    Func<InventoryItemDescription> ItemFunc;
}
public class CryptoWorkbenchSpeedupUpgradeDescription : MyEnumItem {
    float SpeedupModifier;
    Func<InventoryItemDescription> ItemFunc;
}
```

**三个槽位类型 = 三条升级线**：
- 显卡（产出）
- 散热（效率/资源消耗）
- 加速（速度）

**设计含义**：加密矿机是**唯一有"运营成本"的设施**（显卡要电/要散热）。`[实证+推断]`

**注意**：`building_bonus_crypto` = "Increased graphics card performance (**in development**)" → **加密线在原作里没做完**。`[实证-本地化]`

### 2.6 洗钱台（`MoneyWorkbenchDescription`）

```csharp
public class MoneyWorkbenchDescription : MyEnumItem {
    int MaxDirtyCashAmount;                   // 最多能囤多少脏钱
    int SpeedupUpgradesCount;                 // 可装几个加速件
    LaunderingAnalyticsDescription AnalyticsSource;  // 埋点
}
// 升级
public class MoneyWorkbenchSpeedupUpgradeDescription : MyEnumItem {
    float DirtyCashPerPeriodModifier;         // 每周期洗多少脏钱
    Func<InventoryItemDescription> ItemFunc;
}
// 三级台的升级描述
public class MoneyWorkbenchUpgradeDescription : MyEnumItem {
    MoneyWorkbenchSpeedupUpgradeDescription SpeedupDescription;
}
```

**关键字段 `MaxDirtyCashAmount`**：洗钱台**有容量上限**。超过上限的脏钱会怎样？——推测会"溢出"成 `MoneyWorkbenchPoopPileView`（"大便堆"）事件（`LaunderingPoopMessage`）。`[实证：字段/消息；推断：语义]`

### 2.7 采集台（`CollectionTableDescription`）—— 唯一"奖励型"

```csharp
public class CollectionTableDescription : MyEnumItem {
    Func<InventoryItemDescription> InventoryItemFunc;
    CollidersDescription Colliders;
    IReadOnlyList<OBB> Obbs;
    Vector3 InteractPoint;
    InteractDescription InteractDescription;
    Vector3 RewardPosition;          // ← 奖励生成位置
    Vector3 RewardInteractPoint;     // ← 奖励交互点
    Vector3 LootSpawnPoint;          // ← 掉落点
}
```

**三个位置字段**说明采集台有**三段交互**：
1. 在 `InteractPoint` 操作台子
2. 奖励在 `RewardPosition` 生成
3. 在 `RewardInteractPoint` 取奖励
4. 如果被打断/被抢，东西掉在 `LootSpawnPoint`

`[实证+推断]`

**升级**（`[实证-文案]`）：`CollectionTableUpgrade` 槽 × 3 档（Uncommon/Rare/Legendary）→ 解锁更多收集品（`hints_craft_workbench_description` = "Modifying the Collection Table unlocks access to new collections"）。

## 3. Tick 体系：所有设施的时间尺度

| 设施 | 时间字段 | 语义 |
|---|---|---|
| 生产台 | `ResultTickDuration` × `ResultTickCount` | 一次产出的总时长 |
| 充电台 | `TickPeriod` | 一个充能周期 |
| 充电台奖励 | `CollectChargedCargoRewardTime` | 收奖励需要多久 |
| 洗钱台 | （`MoneyWorkbenchData` 的周期） | 每周期洗多少钱 |
| 加密矿机 | （数据侧周期） | 每周期产出 |
| 开箱台 | （物品侧的 `BreachTime` 类似字段） | 开一个箱多久 |
| 采集台 | （模块/升级决定） | 采集周期 |
| 破门 | `DefenseBlock` 的 `BreachTime` | 撬开一道防御多久 |

`[实证：字段存在 / 推断：语义]`

**设计铁律**（`[推断]`）：
> 所有设施的周期必须落在 **秒–小时** 区间，且最好是 **≤12 小时的整数分之一**，让"睡一觉回来"刚好满仓。

## 4. 升级体系的三种模式（这是本系统最值得抄的设计）

ROB RUN 的升级不是"线性升级"，而是**三种正交模式**：

| 模式 | 代表 | 效果 | 玩家的选择 |
|---|---|---|---|
| **速度型** | 开箱台加速件、贸易台加速件、洗钱台加速件 | `SpeedupPercent` / `DirtyCashPerPeriodModifier` | "我要更快" |
| **容量型** | 开箱台加槽件、贸易台加槽件 | `AdditionalSlots` | "我要更多同时处理" |
| **效率/结构型** | 加密矿机散热、生产台权重件 | `ResourceDecreaseModifier` / 权重表 | "我要更省/更好的产出" |

**关键**：**三种模式各占独立槽位**，玩家必须取舍"这台机器我要走哪条线"。`[实证+推断]`

## 5. 产出与掉落的统一规则

**所有设施的产出最终都落到 `SpawnLootPoint`**：

```
工作台 → 完成 → 产出物出现在 SpawnLootPoint（工作台外）
玩家 → 走到 SpawnLootPoint → 长按拾取
若被打断/离线 → 产出物留在地上（可被抢）
```

**为什么不在工作台内部**：与 T06 的"掉落点在门外"同构——**产出必须暴露在可被掠夺的空间**。`[推断]`

## 6. 设施之间的联动

```
开箱台 → 开出货物 → 贸易台（重打包，增值）→ 卖
生产台 → 用试剂产出货物 → 贸易台 → 卖
充电台 → 催熟货物 → 卖/开
加密矿机 → 产出加密货币（独立）
洗钱台 → 脏钱 → 净钱（独立）
采集台 → 收集品（独立，用于图鉴/任务）
```

`[实证：设施存在 + 推断：链路]`

**核心经济闭环**（`[推断]`）：
```
抢劫/购买 → 未开封货物 → 开箱台 → 半成品 → 贸易台 → 高价成品 → 卖 → 脏钱 → 洗钱台 → 净钱
```

## 7. 与既有文档的差异

| 既有结论 | 本文件补充 |
|---|---|
| "5 个工作台 + 采集台" | 实际是 **6 类工作台**（开箱/贸易/生产/充电/加密/洗钱）+ 1 采集台 |
