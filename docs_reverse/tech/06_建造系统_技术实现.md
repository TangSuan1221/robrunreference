## 0. 一页结论

1. **建造不是"自由搭建"，是"往预定义槽位放物品"**。但槽位不是凭空来的：**地块蓝图（`PlotSchemeDescription`）定义了槽位、传送点、掉落点、租牌位置**。
2. **地块蓝图只有一个**：`PlotSchemeDescription.SettlementPlotScheme3`（静态属性），但存在 `PlotGradeDescription` 的"等级"概念（`StartGrade` / `Grade3`，带 `GridBorderSize` + `Scheme`）→ **框架支持多蓝图，内容只做了 1 个**。
3. **六道闸门全部在 `BuilderSlotModel` 的抽象方法里**（类型/冷却/被撬/散落物/二次确认/突袭锁），是所有建造操作的服务端前置校验点。
4. **两类改动配额独立**：`ChangeBuildingExpiringResource`（改建筑）/ `ChangeFurnitureExpiringResource`（改家具），都是 `ExpiringResource`（周期恢复型资源）。
5. **建造面板由 12 个工厂方法组装**（`BuilderSlotsModel.OfPlotScheme/OfMainBuilding/OfOutbuilding/OfCargoOpenWorkbench/...`），每个面板 = `Header + Groups[(groupName, slots[])]`。

`[实证]`

### 1.1 这张表说明的 6 件事

| # | 观察 | 设计含义 |
|---|---|---|
| 1 | **5 组"传送出点"** | 不让玩家"卡墙"：从地块/建造台/车道出来时，服务端指定安全落点 |
| 2 | **每类建筑有独立"掉落点"** | 建筑被撬时，东西掉在**建筑外**（不是原地），避免玩家卡在废墟里 |
| 3 | **`WallObbs` 与 `Obbs` 分开** | 围墙有独立碰撞数据（可被摧毁/可被撬） |
| 4 | **`BlockingCollider`** | 未建成时挡人的碰撞体（`BuilderConstructionBlockingCollidersUpdater` 控制） |
| 5 | **`RentSignPosition` + `RentMarkerPosition`** | 出租牌与地图标记的位置由蓝图定 |
| 6 | **`DiagonalSizeXZ`** | 地块尺寸（用于地图缩放/相机适配） |

### 1.2 地块等级：`PlotGradeDescription`（dump.cs:127293）

```csharp
public class PlotGradeDescription : EnumItem {
    public static readonly PlotGradeDescription StartGrade;
    public static PlotGradeDescription Grade3 { get; }
    public int GridBorderSize;                 // 网格边界尺寸
    public PlotSchemeDescription Scheme;        // 该等级用哪张蓝图
}
```

**关键发现**（`[实证+推断]`）：
- 存在 **`StartGrade`（新手地）** 和 **`Grade3`（3 级地）** 两个等级
- 每个等级绑定**一张蓝图** + **一个网格边界尺寸**
- 但 `PlotSchemeDescription` 当前只有 `SettlementPlotScheme3` 一个实例 → **等级 3 用了唯一的蓝图；StartGrade 可能复用同一张**

→ **"地块是有等级的"**，且等级决定"用哪张蓝图/多大网格"。既有文档说"蓝图只有 1 种"，更准确的说法是：**蓝图类框架支持多张，当前只实例化 1 张，但 `PlotGradeDescription` 已经预留了 `StartGrade` / `Grade3` 两个槽位**。`[实证+推断]`

## 2. 建造的六道闸门：`BuilderSlotModel`（dump.cs:392262）

```csharp
public abstract class BuilderSlotModel : IItemSlotModel {
    public BuilderSlotViewDescription SlotViewDescription;  // 这个槽长什么样
    public int EntityId;                                    // 服务端实体 id
    public IInventoryItemModel InventoryItemModel;          // 槽里现在放的物品
    public abstract InventoryItemDescription InventoryItemDescription { get; }

    // 六道闸门
    public abstract bool CheckType(InventoryItemDescription itemDescription);   // ① 类型
    public abstract bool CheckCooldown(long now);                               // ② 冷却
    public abstract bool IsBlockedByBreachedObjects(long now);                  // ③ 有被撬开的容器
    public abstract bool IsBlockedByLootObjects(long now);                      // ④ 有散落战利品
    public abstract bool CheckShowModalOnMove(long now);                        // ⑤ 需二次确认
    public abstract bool IsBlockedByRaidLock(long now);                         // ⑥ 突袭锁
    public virtual IItemMoveContext CreateMoveContext();                        // 生成移动上下文
}
```

`[实证]`

### 2.1 六道闸门的语义与触发文案（`[实证-文案]`）

| # | 闸门 | 何时为 false | 玩家看到 |
|---|---|---|---|
| ① | `CheckType` | 物品类型不匹配槽位 | 槽位置灰/不可放 |
| ② | `CheckCooldown` | 该槽刚被操作过 | 冷却倒计时 |
| ③ | `IsBlockedByBreachedObjects` | 家里有**被撬开的容器** | `change_builder_has_breach_object_notification_message` = "One or more broken objects prevent performing this action" |
| ④ | `IsBlockedByLootObjects` | 家里有**散落战利品**（没捡完） | 同上的变体 |
| ⑤ | `CheckShowModalOnMove` | 移动会触发风险（如拆主屋） | 弹二次确认 |
| ⑥ | `IsBlockedByRaidLock` | 突袭锁激活中 | `perform_builder_item_action_is_unavailable_due_to_building_is_under_raid_block` = "Cannot edit during raid block" |

**③④ 是最容易被忽略、也最关键的两道**：它们合起来保证"你被入侵时，不能把东西全收进背包"。`[推断]`

### 2.2 搬家专用闸门（`[实证-文案]`）

```
cant_move_plot_when_raid_lock_active = "Cannot relocate under raid block. Wait for: {0:time:}"
```

→ **搬家（`MoveBaseMessage`）单独一条校验**，不在六道闸门里。`[实证]`

## 3. 两块独立配额：改建筑 / 改家具

```csharp
// dump.cs:82918
public class PlotBuildingConfig {
    public int MaxDefensePoints;                                   // 防御点上限
    public FirstAidCabinetDescription BuiltInFirstAidCabinet;      // 内置急救柜（免费送）
    public MainBuildingDescription StartMainBuilding;              // 起始主屋
    public CompoundWallDescription StartCompoundWall;              // 起始围墙
    public ExpiringResourceDescription ChangeBuildingExpiringResource;   // ← 改建筑配额
    public ExpiringResourceDescription ChangeFurnitureExpiringResource;  // ← 改家具配额
}
// dump.cs:64102
public class ExpiringResourceDescription {
    public long BeginTs;
    public long PeriodDuration;   // 每个周期多长
    public int  Count;            // 每周期给几个
    public long Cooldown;         // 冷却
    public int GetPeriodIndex(long ts);
    public long GetPeriodStartTs(int periodIndex);
}
```

`[实证]`

**配额模型**：`ExpiringResource` = **"每 `PeriodDuration` 恢复 `Count` 个，总上限 `Count`"**（周期性恢复，不是线性恢复）。`[实证+推断]`

**两块配额的分工**：
- `ChangeBuildingExpiringResource`：换主屋/附属/围墙
- `ChangeFurnitureExpiringResource`：换储物/货架/工作台/急救柜等

**用途**（`[推断]`）：
1. 防"被入侵时把家改成迷宫"
2. 给"改布局"成本，让布局选择变重
3. 可做付费/时长恢复的商业点

### 3.1 起始建筑（`[实证]`）

`PlotBuildingConfig.StartMainBuilding` / `StartCompoundWall` / `BuiltInFirstAidCabinet` 三个字段 → **租地时白送**主屋 + 围墙 + 一个急救柜。这意味着：

> **玩家租到地的那一刻，就已经有一个"能住、能复活"的最低配置**，不需要先买主屋。

这解释了教程为什么是"租地 → 放主屋"（放的是"起始主屋"，不是买来的主屋）。`[实证+推断]`

## 4. 建造面板的 12 个工厂（`BuilderSlotsModel`，dump.cs:392321）

```csharp
public class BuilderSlotsModel {
    public LocalizedString Header;
    public List<ValueTuple<string, BuilderSlotModel[]>> Groups;   // (分组名, 槽位数组)
    // 12 个工厂
    public static BuilderSlotsModel OfPlotScheme(...);                 // 地块级（主屋/围墙/附属）
    public static BuilderSlotsModel OfMainBuilding(...);               // 主屋内（储物/货架/门/窗/急救柜/房间/工作台）
    public static BuilderSlotsModel OfOutbuilding(...);                // 附属内
    public static BuilderSlotsModel OfCargoOpenWorkbench(...);         // 开箱台
    public static BuilderSlotsModel OfCargoExchangeWorkbench(...);     // 贸易台
    public static BuilderSlotsModel OfCargoProductionWorkbench(...);   // 生产台
    public static BuilderSlotsModel OfCollectionTable(...);            // 收集台
    public static BuilderSlotsModel OfMoneyWorkbench(...);             // 洗钱台
    public static BuilderSlotsModel OfCargoChargeWorkbench(...);       // 充电/催熟台
    public static BuilderSlotsModel OfDefenseBlock(...);               // 防御块
    // 两个内部工具
    private static void AddCollectionTable(...);
    private static void AddCargoWorkbenches(...);
    private static void AddFirstAidCabinets(...);
}
```

**关键设计**：**每个可交互对象都有自己的"建造面板"**，且面板内容由"该对象的描述 + 实体 id + 模型 + 防御块"四者拼出来。`[实证]`

### 4.1 工厂入参说明什么（`[实证+推断]`）

| 入参 | 说明 |
|---|---|
| `XxxViewDescriptions` | 视图描述（图标/名称/槽位外观） |
| `XxxEntityIds` | 实体 id 容器（每个槽一个 id） |
| `XxxModel` | 运行时模型（当前放了什么） |
| `DefenseBlockPublicModel` | **防御块**——建造面板会感知"这个对象有没有防御块" |
| `ExpiringResourceModel` | **配额**——建造面板会感知"还剩几次改动" |

→ **建造面板不是静态 UI，它同时读"描述/实体/模型/防御/配额"五路数据**。`[实证+推断]`

### 4.2 面板结构（`BuilderSlotsModel` + `BuilderDialogView`）

```
BuilderDialogView
 ├ Header（LocalizedString，如"Main Building"）
 ├ ScrollRect
 └ BuilderGroupView[]（每个 Group 一个页签/分组）
      └ BuilderSlotView[]（每个槽一个格子）
```

`[实证：类存在]`

## 5. 建造交互链（完整版）

```
① 玩家走到地块的 PlotUnlockBuilder（建造台）
     → PlotUnlockBuilderTargetProvider 检测交互
     → 解锁建造面板
② 打开 BuilderDialogView
     → BuilderSlotsModel.OfPlotScheme(...) / OfMainBuilding(...) 组装面板
③ 玩家从背包拖一件建筑物品到某个槽
     → BuilderSlotModel 六道闸门校验
     → 生成 IItemMoveContext
     → 发 RPC：FromInventoryToBuilderMessage(entityId, slot) / SwapBuilderWithInventoryMessage(...)
④ 服务端写 Database*Data + EntityId
     → 复制回客户端（Models.Replication）
⑤ 视图层重建
     → PlotMainBuildingView / PlotOutbuildingView / PlotCompoundWallView
     → BuilderConstructionBlockingCollidersUpdater 更新"挡人碰撞体"
     → PlotCarveTerrainViewUpdater 挖地形
```

`[实证：类/消息存在；推断：时序]`

### 5.1 8 条建造 RPC（`[实证]` `Models.Messages.Builder`）

| RPC | 语义 |
|---|---|
| `BuyPlotMessage(int spotIndex)` | 租地 |
| `MoveBaseMessage(int spotIndex)` | 搬家 |
| `BuilderUnsetMessage(int entityId)` | 清空某槽 |
| `FromInventoryToBuilderMessage(int entityId, InventorySlotDescription slot)` | 背包 → 槽 |
| `FromBuilderToInventoryMessage(int entityId, InventorySlotDescription slot)` | 槽 → 背包 |
| `SwapBuilderMessage(int firstSlotEntityId, int secondSlotEntityId)` | 槽 ↔ 槽 |
| `SwapBuilderWithInventoryMessage(int entityId, InventorySlotDescription fromSlot, InventorySlotDescription toSlot)` | 槽 ↔ 背包（指定位置） |
| `CheckSpawnLootOnSwapBuilderWithInventoryMessage(int entityId, InventorySlotDescription inventorySlot)` | **交换前问服务端"这一换会不会掉东西"** |

**最后一条是精髓**：`CheckSpawnLootOnSwapBuilderWithInventory` = 有些槽里放着"会掉落的战利品"（如被撬开的容器），把它换走会**生成掉落物**——所以客户端必须先问服务端。`[实证+推断]`

## 7. 建造与"生存/防御/经济"的交点

| 交点 | 机制 |
|---|---|
| 建造 ↔ 生存 | 急救柜提供复活点（`hints_first_aid_cabinet_description`） |
| 建造 ↔ 防御 | 每栋建筑有 `DefenseBlock` 挂点（`PlotDefenseBlockDescription`） |
| 建造 ↔ 经济 | 工作台是生产设施（T07） |
| 建造 ↔ PvP | 容器可被撬（`bool BreachWithoutKey` + `long BreachTime`） |
| 建造 ↔ 载具 | 车位/直升机位（T12） |
| 建造 ↔ 室内 | 房间容器（`PlotContainerDescription` 7 种房间） |
