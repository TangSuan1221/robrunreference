## 0. 一页结论

1. **防御是一条单轴数值**：`DefensePoints`。它由 **防御块基础值 + 防御模块 + 聚落公共建筑加成** 三段叠加而成，计算链完全可读。
2. **进攻方也是单轴**：`PlotBuildingDecoderDescription.DefensePoints` —— 解码器与防御块**用同一个数值轴对比**。
3. **防御块有 3 个状态**（`DefenseBlockState { Active, Raiding, Raided }`），而不是布尔值。
4. **`RaidLockTs` 是"时间戳权威"**：客户端按时间戳判定"锁有没有过期"，不需要服务端推送。
5. **警报有"队列 + 显示延迟 + 优先级"**：`PlotAlarmNotificationModel` 是一个按 `Ts/PublicId/Priory` 排序的通知队列，`_showingDelay = 1000ms`。
6. **警报有 3 种范围**（自我/用户/带聚落的用户），对应 3 套文案。

### 1.2 三种模块

```csharp
// 普通防御模块（加防御点）
public class DefenseBlockDefenseModuleDescription : EnumItem {
    int DefensePoints;
    Func<InventoryItemDescription> ItemFunc;
}
// 特殊模块（功能型，不加防御点）
```

`[实证]`

**关键区分**：
- **普通模块**（`DefenseModuleSlots`）→ 只加 `DefensePoints`
- **特殊模块**（`SpecialModuleSlots`）→ 只提供功能（警报），**不加防御点**

`[实证+推断]`

`[实证]`

**三个数据类的分工**：

| 类 | 谁看 | 含什么 |
|---|---|---|
| `DatabaseData`（服务端） | 服务端 | 全部 + `RaidId` + 埋点标志 |
| `PrivateData` | **房主** | 模块配置 + 防御点 |
| `PublicData` | **入侵者/路人** | 只有 `RaidLockTs` / `IsRaided` / `IsSlotsEmpty` |

→ **入侵者看不到防御块的模块配置，只能看到"是否已被突袭/锁到何时"**。这是信息不对称设计。`[实证+推断]`

```csharp
public class PlotBuildingDecoderDescription : MyEnumItem {
```

`[实证]`

**攻防判定**（`[推断]`）：
```
if (Decoder.DefensePoints >= DefenseBlock.DefensePoints) → 可撬，耗时 CastDuration

```

**为什么叫 `DefensePoints` 而不是 `AttackPoints`**：因为**同轴**——攻防用同一个数值名称，便于直接比较。`[实证字段名 + 推断]`

**攻防的"物品"**（`[实证-本地化]`）：
```

defense_block_module_defense_stat_name   = "Defense"
```

→ 防守方用 **Fuse（保险丝）**，进攻方用 **Decoder（解码器）**。`[实证]`

## 4. 突袭锁（Raid Lock）

### 4.1 数据结构（`[实证]`）

| 字段 | 位置 | 语义 |
|---|---|---|
| `RaidLockTs` | `DefenseBlockDatabaseData` / `PublicData` / `MainBuildingData` | 锁到期时间戳 |
| `IsRaided` | 同上 | 是否已被突袭 |
| `RaidId` | `DatabaseData` | 本次突袭的唯一 ID（**用于防重放/关联日志**） |
| `NeedSendRaidLockEndAnalytics` | `DatabaseData` | 锁结束要发埋点（说明"锁结束"是重要事件） |
| `string RaidId` | `LocationPlotAlarmNotificationData` | 关联警报 |

### 4.2 锁的语义（`[实证-文案 + 推断]`）

```
perform_builder_item_action_is_unavailable_due_to_building_is_under_raid_block = "Cannot edit during raid block"
cant_move_plot_when_raid_lock_active = "Cannot relocate under raid block. Wait for: {0:time:}"
```

**锁冻结的东西**：
1. 建造编辑（六道闸门第⑥道）
2. 搬家（`MoveBaseMessage` 单独校验）

**锁不冻结的东西**：
- 可以上线、可以看、可以跑、可以捡散落物
- 可以修防御（`ResetPlotBuildingRaidLockTimeMessage` 可重置锁时间）

`[推断]`

### 4.3 锁的"重置"（`[实证]`）

```
ResetPlotBuildingRaidLockTimeMessage   // 重置某建筑的锁
ResetSelfPlotRaidLockTimeMessage       // 重置自己地块的锁
```

**为什么需要重置**：防御块被修复/重建后，锁可能应该延长或清除。这是服务端裁决。`[推断]`

## 5. 警报系统：队列 + 延迟 + 优先级

### 5.1 通知模型（`[实证]` dump.cs:443463）

```csharp
public abstract class PlotAlarmNotification {
    public long Ts;
    public long PublicId;    // 被警报者的公开 ID
    public int  Priory;      // 优先级（原文拼写 Priory）
}
```

**三个子类**（`[实证]`）：
```csharp
PlotAlarmNotification.Self               // 自己家被入侵（443395）
PlotAlarmNotification.User               // 别人家被入侵（443192）
PlotAlarmNotification.UserWithSettlement // 别人家被入侵 + 知道聚落名（443277）
```

**为什么分三种**：
- `Self`："Your base is under attack!"
- `User`："{0}'s base is in danger!"
- `UserWithSettlement`："{0}'s base in {1} is being breached!"（**带位置**，用于帮派/地点频道）

`[实证+推断]`

### 5.2 队列机制（`[实证]` dump.cs:443169）

```csharp
public class PlotAlarmNotificationModel {
    private const long _showingDelay = 1000;   // 1 秒
    private readonly Dictionary<long, PlotAlarmNotification> _notificationsQueue;  // 按 Ts 索引
    public void TryEnqueue(PlotAlarmNotification notification);
    public bool TryPeek(long now, out PlotAlarmNotification notification);
    public bool TryDequeue(long now, out PlotAlarmNotification notification);
}
```

**关键**：
- **队列按 `Ts` 索引**（`Dictionary<long, PlotAlarmNotification>`）
- **显示延迟 1 秒**（`_showingDelay = 1000`）
- `TryPeek` / `TryDequeue` 都带 `now` → **按当前时间判断"能不能显示"**

→ **警报是"排队播放"的**，不是"同时弹出 5 条"。`[实证+推断]`

### 5.3 延迟警报（`DeferredAlarmView`，dump.cs:262150）

```csharp
public class DeferredAlarmView : MonoBehaviour {
```
