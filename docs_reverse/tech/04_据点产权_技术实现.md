## 0. 一页结论

1. **聚落买断**与**地块租赁**是两套完全独立的系统，用**两种不同物品**结算：
   - 聚落：`Settlement Title`（Tier 1/2/3），入口 `BuySettlementMessage(sector, settlement, settlementName)`
   - 地块：`Land Plot Title`（Tier 1/2/3），入口 `RentPlotDialogModel.OpenDialog(spotIndex)` → `BuyPlotMessage(spotIndex)`
2. **价格不是现金，是物品清单**：`SettlementPriceRules` 提供 5 个价格/3 个支付 API，全部按 `(sector, settlement, realmVersion)` 查表。
3. **驱逐（Evict）是聚落主对居民的单向权力**：`EvictConfig { PriceItem, CastTime }` + `EvictPlot` 流程；被驱逐方"可保留一部分资产"，但**必须撬开其全部安防系统**才能驱逐。
4. **聚落改名有 5 条校验**（长度/纯数字/特殊字符/首尾空格/连续空格）+ 重名 + 举报。
5. **地主 UI 是双页签**（`LandOwnershipTabs { Settlements=0, Robbing=1 }`）：一页管"我拥有的"，一页管"我能抢的"。

## 1. 两种产权：对照表

| 维度 | 聚落（Settlement） | 地块（Plot） |
|---|---|---|
| 购买凭证 | `SettlementTitle` 物品（Tier1/2/3） | `LandPlotTitle` 物品（Tier1/2/3） |
| 数量上限 | `OwnedSettlementConfig.MaxCount` | 每人 **1** 块（换租=搬家） |
| 前置 | 该区 `TierParams.CanBuySettlement = true`；聚落当前无主/可转让 | 聚落**有主**；自己无地（或换租）；区 Tier 匹配地券档位 |
| 成功后 | 成为 `OwnedSettlementData` 的 Owner；可收税、可免费拿地、可驱逐 | 成为地块租户；`SettlementPlotDatabasePartData` 绑定玩家 |
| 价格 | `GetSettlementItemsPrice(sector, settlement, realmVersion)` | `GetPlotItemsPrice(...)` |
| 本地迁移 | — | `GetLocalMovePlotItemsPrice(sector, realmVersion)`（同区换地更便宜） |
| 能否被抢 | **不能**（`realm_own_dialog_description_2` = "No one can take away purchased land"） | **不能**（地块本身不在掠夺范围） |
| 失去方式 | 主动放弃 / 州末没收 / 服务端回收 | 主动换租 / 驱逐 / 州末没收 |

`[实证：字段/API/文案；值为服务端]`

## 2. 价格系统：`SettlementPriceRules`（dump.cs:741）

```csharp
public static class SettlementPriceRules {
    // 5 个价格查询
    public static InventoryItemsPrice GetPlotItemsPrice(SectorDescription sector, SettlementDescription settlement, RealmVersion realmVersion);
    public static InventoryItemsPrice GetSettlementItemsPrice(SectorDescription sector, SettlementDescription settlement, RealmVersion realmVersion);
    public static InventoryItemsPrice GetLocalMovePlotItemsPrice(SectorDescription sector, RealmVersion realmVersion);
    // 3 个"够不够"校验
    public static bool CheckPlotItemsPrice(IInventoryModel inventory, SectorDescription sector, SettlementDescription settlement, RealmVersion realmVersion);
    public static bool CheckLocalMovePlotItemsPrice(IInventoryModel inventory, SectorDescription sector, RealmVersion realmVersion);
    public static bool CheckSettlementItemsPrice(IInventoryModel inventory, SectorDescription sector, SettlementDescription settlement, RealmVersion realmVersion);
    // 3 个"扣款"执行
    public static void PayPlotItemsPrice(...);
    public static void PayLocalMovePlotItemsPrice(...);
    public static void PaySettlementItemsPrice(...);
    // 合并工具
    public static IReadOnlyList<InventoryItemWithAmount> ConcatenateAsList(InventoryItemsPrice[] prices);
}
```

**四个设计含义**（`[推断]`）：

1. **价格是"物品清单"**：`InventoryItemsPrice = IReadOnlyList<InventoryItemWithAmount>`（类集合见 `InventoryItemsPriceDescription` dump.cs:64293）。所以"买地"在数值上是"交出 N 种物品各 M 个"，不是扣钱。
2. **价格随 `(sector, settlement)` 变化**：同一个 Tier，不同区/不同聚落可以不同价（`SectorParams` 也可用 `TierParams` 的基准价）。
3. **`LocalMovePlotItemsPrice` 是"同区换地"的折扣价**：证明"搬家"是一条独立定价路径。
4. **`ConcatenateAsList` 说明一次交易可以合并多个价格表**（如"聚落 + 其公共建筑"打包价）。

### 2.1 价格来源（`TierParams`，dump.cs:80017）

```csharp
public class TierParams {
    public bool CanBuySettlement;
    public InventoryItemsPriceDescription PlotPrice;
    public InventoryItemsPriceDescription SettlementPrice;
    public InventoryItemsPriceDescription BuildingPriceForSettlement;
    public InventoryItemsPriceDescription BuildingPriceForPlot;
    public InventoryItemsPriceDescription LocalMovePlotPrice;
    // 税率
    public float SettlementWithoutOwnerTax;     // 无主时的税（归系统？）
    public float SettlementWithOwnerTax;        // 有主时的税（归业主）
    public float SettlementPurchaseTax;         // 购买时的交易税
    public float SectorWithOwnerTax;            // 区有主时的税

```

→ **Tier 不只是"区等级"，它是一个"经济参数包"**：价格、税率、洗钱速度、帮战门槛全在里面。`[实证]`

### 2.2 客户端如何知道"这件物品能抵多少价"（`[实证]`）

`GetItemAmountsForSettlementPriceMessage(TierDescription tier)`（dump.cs:202054）：
- 客户端只发 **Tier**，不带具体物品；
- 服务端返回该 Tier 下"可用于抵扣的物品 → 数量"表；
- 客户端据此显示 `rent_dialog_condition_item_description` = "{0} ({1}/{2})"（物品名 / 已有 / 需要）。

**为什么这样设计**：物品折算率是经济数值，必须服务端权威；客户端只负责显示"你还差几个"。`[推断]`

`[实证]`

### 5.1 驱逐规则（`[实证-文案]`）

| 文案 | 原文 |
|---|---|
| `evict_plot_1_name` | "Eviction Right" |
| `evict_plot_1_description` | "Evicts the player from the plot and dispossesses them of their assets on it. You can keep a portion of the assets for yourself after eviction. **The title is applied to the Plot Plan. To evict a player, you must hack all security systems at their base.**" |
| `eviction_progress` | "Evicting..." |

**三条硬规则**（`[实证]`）：

1. 驱逐 = **把「Eviction Right」物品用在目标的 Plot Plan 上**（不是点菜单）。
2. **必须先撬开目标的全部安防系统**（防御块/模块）→ 驱逐是"打完才能驱逐"，不是"业主一键踢人"。
3. 驱逐后**业主可以保留一部分资产**（`[未知]` 保留比例）。

**设计含义**：这条把"驱逐"从"权力"变成"武力行为"——业主想清人，必须亲自/带人打进那栋房子。`[推断]`

### 5.2 驱逐与突袭的关系

```
普通突袭：撬开容器 → 拿东西（拿完就走，房子还在）
驱逐：撬开全部安防 → 用 Eviction Right → 人走、地归业主、资产部分保留
```

→ 驱逐是**突袭的终局形态**，需要更高的投入（撬完全部安防）。`[推断]`
