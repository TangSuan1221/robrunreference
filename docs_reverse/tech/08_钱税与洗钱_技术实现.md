## 0. 一页结论

1. **货币是三层**：`DirtyCash`（脏钱，物品）→ `CleanCredits`（净钱，账户）→ `Coins`（硬通货，付费/战令）。洗钱台负责第一层→第二层。
2. **洗钱是"tick + 分段加成"**：`MoneyWorkbenchBonusConfig.BonusPerAmount[]` 是**按脏钱量分段的加成表**（`Amount` → `Bonus`），加上"电缆损坏惩罚"（`BrokenCablePenaltyPercent`）。
3. **税有两条线**：**聚落税**（`TaxType.Settlement`，洗钱流水抽成，归业主）与**帮派税**（`TaxType.Clan`，控制产业/区，归帮派）。
4. **税不是"钱"，是"一堆现金实体"**：收税时会在 `TaxPointView` 生成 `TaxCashView` 现金堆，**附近所有人可拿**（`tax_collection_safe_description`）。
5. **现金锁（Cash Lock）** 是税/大额现金的"重算期"：`CashLockedAmount` + `CashLockEndTs`，期间不可取（`unavailable_by_tax_cash_lock` = "Tax amount is being recalculated"）。

### 2.1 洗钱状态机（`[实证+推断]`）

```
[空闲] --StartLaundering--> [洗钱中] --每 tick--> Dirty -= rate, Clean += rate
   ^                            |
   |                            └--StopLaundering--> [空闲]（记录 LastTickTs）
   |
   └--电缆断--> [故障] --RepairBrokenCableDuration--> [空闲]
```

**四个关键行为**：
- `StartLaundering(now)` / `StopLaundering(dirty, clean, lastTickTs)`：**开关式**，不是"一单一单"
- `TakeDirty(amount)`：随时可取回脏钱（停止洗）
- `Poop(publicId)`：**"大便"事件** —— 谁触发的、谁被记录（`PoopPilePlacers`）

### 2.2 "大便堆"事件（`[实证+推断]`）

**推断语义**：洗钱台满了（`DirtyAmount > MaxDirtyCashAmount`？）或洗钱过程中被入侵，会生成"大便堆"（`PoopPile`），**记录是谁导致的**（`PublicId`）。这是**羞辱性反馈**：你洗钱洗崩了，地上留一坨，别人能看到是谁的。`[推断]`

> 这是一个非常"Kefir 式"的设计：用**羞辱**替代**惩罚**。`[推断]`

`[实证]`

**语义**（`[推断]`）：
- `BonusPerAmount[]`：**按当前脏钱量给加成**。例如 `{Amount:1000, Bonus:5%}` = 囤到 1000 时洗钱速度 +5%
- 这是一个**反挂机的曲线设计**：要么"少量高频"（不加成），要么"大量低频"（加成但风险大）
- `BrokenCablePenaltyPercent`：电缆被破坏时，洗钱速度打折
- `RepairBrokenCableDuration`：修复时长（读条）

**与 UI 的对应**（`[实证-文案]`）：
- `money_workbench_speedup_1_name` = "Banknote Counter"（点钞机，加速件）
- `laundering` = "Laundering (per hour)"
- 洗钱 tooltip 的四源加成：`speedByModules` / `speedByProtect` / `speedByAmount` / `speedByVip`（`MoneyLaunderingTooltipsUpdater`）

| 乘区 | 来源 | 设计意图 |
|---|---|---|
| `speedByModules` | 洗钱台装的加速件 | 建造投入 |
| `speedByProtect` | 聚落保护等级（公共建筑 bunker/保安） | **业主建防御 → 居民洗得快 → 税收多** |

**这就是"聚落主—居民"唯一的正和闭环**（`[推断]`）：
```
业主建 bunker → speedByProtect↑ → 居民洗钱快 → 居民洗得多 → 业主抽税多
```

## 5. 现金锁（Cash Lock）

```csharp
// dump.cs:8658
SettlementTaxExtensions.RecalculateSettlementCashDataForTs(long ts, int cashLockedAmount, long cashLockEndTs, int cashAmount);
// SettlementTaxDescription
public static long CashLockDuration { get; }
```

**语义**（`[实证+推断]`）：
- **现金锁 = 一笔钱在"重算"期间被冻结**
- `CashLockedAmount`：冻结多少
- `CashLockEndTs`：什么时候解冻
- `RecalculateSettlementCashDataForTs(...)`：**按时间戳重算现金数据**（服务端权威）
- 文案：`unavailable_by_tax_cash_lock` = "Tax amount is being recalculated"

**为什么需要**：税是**流水抽成**，而流水在实时变化。收税时先"锁住当前金额"，重算完再发放——防止"边收边涨"导致重复发放。`[推断]`
