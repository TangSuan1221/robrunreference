## 0. 一页结论

1. **交互的原子单位是"长按进程"（Prolonged Interaction）**：玩家按住一个键，服务端计时，完成/中断。32 种互斥进程 = 32 种"你在做什么"。
2. **目标提示（Target Hint）是"我能不能对这个东西做什么"的显示器**：它由 `ITargetProvider` 提供数据、`TargetHintView` 显示、`UnavailableTargetActionsKeys` 解释"为什么不能"。
3. **共享打开态用引用计数**：`InteractableObjectOpenedModel` 用 `HashSet<int> _interactingCharacters` 推 `IsOpened`（A 走 B 还开着 → 不关）。
4. **独占占用用单值槽位**：`HideObjectModel` 用 `int _entityId` + `_emptyEntityId = -1`。
5. **弹窗是"单例栈"**：`ModalDialogModel.OpenDialog(data)` / `IsOpened(data)` / `CloseDialogIfOpened(data)` —— **同一个弹窗不重复开**。

## 1. 长按交互（Prolonged Interaction）—— 交互的原子单位

### 1.1 抽象基类（`CommonProlongedInteractionHandlerModel`，dump.cs:162109）

```csharp
public abstract class CommonProlongedInteractionHandlerModel : ICommonProlongedInteractionHandlerModel {
    public abstract MutuallyExclusiveProcessesDescription Process { get; }   // 我在干什么
    internal abstract UseEntityCommandDescription StartCommand { get; }      // 开始命令
    internal abstract UseEntityCommandDescription StopCommand { get; }       // 结束命令
    public void SetRequest(UseEntityCommandDescription command, int useEntityId,
        RequestModel<ValueTuple<ProlongedInteractionInputDescription,
                                MutuallyExclusiveProcessesDescription, int>> request);
    public abstract bool CheckInteractionStart(UseEntityCommandDescription command, int useEntityId, PlayerRoleDescription playerRole);
    public abstract bool TryFinishPrediction(long now, BattleCharacterModel characterModel);
    public abstract bool TryGetTargetPosition(int entityId, out Vector3 position);
    public abstract void HandelRequest(long now, int entityId,
        ProlongedInteractionInputDescription prolongedInteractionInput, BattleCharacterModel characterModel);
}
```

`[实证]`

**四件套**：`Process`（互斥类别）+ `Start/Stop Command`（命令）+ `CheckInteractionStart`（能不能开始）+ `TryFinishPrediction`（客户端预测）。

**这是"局外系统"的全部长按动作清单**（32 个）。每个动作都对应一个 `*TargetProvider` + `*TargetHintUpdater`。`[实证]`

### 1.3 交互的三态（`[实证：类名]`）

| 态 | 类 | 表现 |
|---|---|---|
| **可用** | `TargetProvider.GetTargetAction()` 返回有效 action | 显示"按 E 撬开" |
| **不可用（有原因）** | `UnavailableTargetActionsKeys` | 显示"需要解码器" |
| **不可见** | 无 target | 不显示提示 |

## 2. 目标提示（Target Hint）的 UI 栈

```
ITargetProvider（数据源）

       ├ 每个可交互物一个子类（约 60+ 个，见下）
       └ GetTargetAction() → ITargetAction
```

## 3. 共享打开态：引用计数（`InteractableObjectOpenedModel`，dump.cs:174892）

```csharp
public class InteractableObjectOpenedModel {
    private readonly IPrimitiveData<bool> _data;         // 服务端同步的打开态
    private readonly HashSet<int> _interactingCharacters; // 谁在交互
    public bool IsOpened { get; }
    public void AddInteractingCharacter(int entityId);
    public void RemoveInteractingCharacter(int entityId);
    private void UpdateOpenedState();   // IsOpened = #characters > 0
}
```

`[实证]`

**语义**：**A 打开箱子、B 也打开、A 走 → 箱子不关**（因为 B 还在）。这是"共享打开"的正确实现。`[推断]`

**零 RPC**：`_data` 是同步的，但 `Add/RemoveInteractingCharacter` 是**纯客户端**的（不进 `IPrimitiveData`）→ **读操作不发 RPC**。`[实证+推断]`

## 4. 独占占用：单值槽位（`HideObjectModel`，dump.cs:176027）

```csharp
public class HideObjectModel {
    private const int _emptyEntityId = -1;
    private int _entityId;
    public bool IsEmpty => _entityId == _emptyEntityId;
    public void Set(int entityId);
}
```

`[实证]`

**语义**：一个藏身点只能一个人。`Set(entityId)` 写入，`_emptyEntityId = -1` 表示空。`[实证]`

**与共享打开态的区别**：

| | 共享打开 | 独占占用 |
|---|---|---|
| 数据结构 | `HashSet<int>` | `int` 单值 |
| 语义 | 多人可同时 | 只能一人 |
| 冲突 | 无 | 第二人被拒 |
| 例子 | 储物箱 | 藏身点/衣柜 |

## 5. 弹窗管理：单例栈（`ModalDialogModel`，dump.cs:449978）

```csharp
public class ModalDialogModel : ScreenModel {
    public ModalDialogData DataModel { get; set; }
    public bool IsOpened(ModalDialogData model);
    public void CloseDialogIfOpened(ModalDialogData model);
    public ModalDialogBuilder CreateBuilder();
    public void OpenDialog(ModalDialogData model);
}
```

`[实证]`

**语义**：
- `IsOpened(model)`：某个弹窗是否已开
- `CloseDialogIfOpened(model)`：如果开着就关（**防重复/防竞态**）
- `OpenDialog(model)`：打开
- `CreateBuilder()`：用 Builder 模式构造弹窗（`ModalDialogData` 描述内容）

**"单例"体现在 `IsOpened(model)`**：同一个 `ModalDialogData` 不会开两次。`[实证+推断]`

## 7. 提示文案的"三段式"（`[实证-文案]`）

ROB RUN 的目标提示常用三段结构：

```
[动作] [条件] [后果]
```

例：
- `breach_unavailable_because_of_item_is_missing` = "{0} required in the inventory"（**条件缺失**）
- `perform_builder_item_action_is_unavailable_due_to_building_is_under_raid_block` = "Cannot edit during raid block"（**状态禁止**）
- `change_builder_has_breach_object_notification_message` = "One or more broken objects prevent performing this action"（**前置未满足**）

**规律**：所有"不可用"提示都遵循 **"谁能做什么 / 为什么不行"** 的格式。`[推断]`

## 8. 交互 UI 的 5 个"必测"场景（`[推断]`）

| # | 场景 | 期望 |
|---|---|---|
| 1 | 两人同时开同一箱子 | 共享打开态（不关） |
| 2 | A 开后 B 关，A 还在操作 | 箱子应保持开（引用计数） |
| 3 | 两人同时抢同一藏身点 | 第二人看到"Cover occupied" |
| 4 | 撬锁中被打断 | 进度回退，提示消失 |
| 5 | 弹窗开着时状态变化（如 Raid Lock 生效） | 弹窗自动关闭（`CloseDialogIfOpened`） |
