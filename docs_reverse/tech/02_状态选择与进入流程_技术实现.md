## 0. 一页结论

1. "局外"的入口是一条 **单向状态机**：`主菜单 → 选大区 → 选州 → 载入州 → 落点`；换州/换区是**另一条命令流**（`INetworkCommand`），不走"返回主菜单"。
2. 州列表的每一行是 `RealmEntryView`，由 **6 个状态元素**驱动（占用/推荐/选中/年龄/大小/好友）。
3. **本地有一份完整的"列表展示参数" ScriptableObject**：`SwitchRealmViewDescription`，其中 8 个数值已在本机解出（见 §3.2）——这是本次逆向**唯一能拿到真数值的局外配置**。
4. 州信息是**分源订阅**的：`RealmInfoSource` 是 6 位标志位（人口/聚落归属/帮战区/帮战产业/聊天/最新州），每个 UI 只订阅自己需要的源。
5. 进入失败有 **6 类明确文案**（满员/老州/无主聚落/无家/队伍未齐/区进入错误），全部可核对。

`[实证]`

**关键观察**：
- `SwitchRealmCommand` 携带的是**整个 `RealmEntry`**（含 `StartTs`/`Version`/`UserCount`），不是裸 `realmId` → 服务端可校验"你选的是不是你看到的那台"（防止列表刷新后的错位进入）。`[推断]`
- `SwitchRegionCommand` 用的是 **`RegionClusterDescription`**，不是 `string region` → 大区在代码里是**可配置对象**（有 id/index/显示名），不是硬编码字符串。`[实证]`
- 三条命令都是 `INetworkCommand` → 走网络命令通道，不是 UI 状态机本地切换。`[推断]`

### 2.2 `RealmInfoSource`：6 位标志位（`[实证]` dump.cs:161348）

```csharp
public enum RealmInfoSource : byte {
    None                  = 0,
    SettlementPopulation  = 1,   // 每聚落人口
    OwnedSettlements      = 2,   // 聚落归属（谁买的）
    ClanConquestSectors   = 4,   // 帮派占区

```

**这是"按需订阅"的证据**：`RealmInfoSourceModel`（dump.cs:415828）用 `IsReady(source)` / `IsChanged(source)` 做位测试；`SubscribeRealmInfoMessage`（dump.cs:202910）+ `SubscribeRealmInfoUpdater`（dump.cs:415576）是订阅入口。

**设计含义**：打开州列表**不需要**下载全部 10 区 × N 聚落的人口；只有地图/聚落卡片页才订阅 `SettlementPopulation`。这是"单州塞很多人"的关键优化。`[推断]`

### 3.2 `SwitchRealmViewDescription` 的真数值（`[实证-本地SO]` path_id `7245226053162067993`）

| 字段 | 值 | 含义 |
|---|---|---|
| `TimeRealmOldThreshold` | **86,400,000 ms = 24 h** | 州存在超过 24h 即视为"老州"，显示 RUN TIME 提示与风险文案 |
| `LowRealmOccupancyPercent` | **0.20** | 人口/上限 < 20% → `Low` |
| `MediumRealmOccupancyPercent` | **0.825** | < 82.5% 且 ≥20% → `Medium`；≥82.5% → `High`；=100% → `Full` |
| `RecommendedRealmsCount` | **3** | 列表里标"Recommended"的州数量上限 |
| `IsFakeRealmSizeEnabled` | **1（true）** | **启用"假人口"机制** |
| `FakeRealmSize` | **15,000** | 假人口显示值 |
| `FriendsTooltipNicknamesCount` | **10** | 好友 tooltip 最多列 10 个昵称 |

> ⚠️ **`IsFakeRealmSizeEnabled` + `FakeRealmSize = 15000` 是本次逆向最"产品化"的发现**：新州真实人口很少时，列表显示 15,000，用于让新州看起来有人气（社交证明/避免空服劝退）。这是**可复刻的运营手段**，不是 bug。

### 3.3 `RealmEntryView` 的 6 个状态元素（`[实证]` dump.cs:416188）

```csharp
public class RealmEntryView : MonoBehaviour {
    EnumStateElement<LineOccupancy>   _lineOccupancyState;   // Normal / Full（列表行视觉）
    EnumStateElement<RealmOccupancy>  _realmOccupancyState;  // Low/Medium/High/Full
    EnumStateElement<RealmEntrySelection> RealmSelectionState;   // Unselected / Selected
    EnumStateElement<RealmRecommendation> RealmRecommendationState; // NotRecommended / Recommended
    TextLabel<string,int> RealmIdLabel;          // "{Region} {RealmId}"
    TextMeshProUGUI RealmNameLabel;              // "Golden Valley"
    TextLabel<bool,bool,TimeSpan> RealmAgeLabel; // 年龄（含"是否老州"布尔）
    TextLabel<int> RealmSizeLabel;               // 人口
    RectTransform OldRealmTooltipContainer;
    CompositeButtonView Button, TooltipButton;
    SwitchRealmFriendsView Friends;

```

**两个占用枚举不是重复**：`LineOccupancy` 是"这一行是否显示为满"（视觉行状态），`RealmOccupancy` 是"州的人口档位"（4 档）。`[推断]`

## 7. 搜索州 ID 的校验链（`[实证]`）

```csharp
// SwitchRealmLocalization 的 5 条文案（path_id -3955775674806922645）
InputStringInvalidLength  → "Enter your ID using Latin letters and digits"
InvalidRealm              → "Numeric part of ID must be greater than {0}"
FindRealmByIdUnexpectedError → （服务端异常）
FindRealmByIdCooldown      → （搜索冷却）
RefreshRealmsCooldown      → （刷新冷却）
```

**配合 `RealmId.Validate(int)`**：`realmId > 999` 且 `≤ int.MaxValue`。`[实证]`

**配额字段**：`RealmConfig.RealmsListExpiringResource`（列表刷新）与 `SearchRealmByIdExpiringResource`（按 ID 搜索）——**两个配额分开算**，搜索比刷新更贵。`[实证+推断]`

## 8. 与"进入聚落/地点"的边界

选州只是"进入这台服务器"。**进入具体空间**还有第二层校验（T03/T04）：

```
选州成功 → 在 Global Map（州地图）
  ├ 进聚落：需 (a) 聚落有主 (b) 自己有地 (c) 队伍全员满足
  ├ 进城市/监狱/区中心：需 (a) 位置合法 (b) 队伍全员可进
  └ 进自己的地块：需在聚落内，且不在 Raid Lock 的搬家限制下
```

对应 `FindSettlementCommand` / `StartPartySettlementCommand` / `FindHubCommand` / `EnterPrisonCommand` 等（见 T16 的命令清单）。`[实证：类存在]`
