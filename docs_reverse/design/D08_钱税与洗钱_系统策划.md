---

## 1. 经济系统的核心命题

> **"让钱脏着进来，干净着出去，中间每一步都能被抢。"**

ROB RUN 的经济是一条**有摩擦的管道**：

```
抢/买（脏钱/货物） → 加工（加价） → 卖（脏钱） → 洗（净钱）
                                    ↑
                              每一步都能被抢/被税
```

**设计铁律**：
> 如果某一步"不可被抢"，它就是安全存钱罐，整个经济会向那一步塌缩。
>
> ROB RUN 的做法：**连"税"都是掉在桌上的现金堆**。

---

## 2. 三层货币与它们的"人格"

| 货币 | 玩家叫法 | 特性 | 它逼玩家做什么 |
|---|---|---|---|
| **Dirty Cash** | "现金" | 可被抢、可被抓、有重量 | 尽快花掉或洗掉 |
| **Clean Credits** | "余额" | 安全、可数字支付 | 长期积累 |
| **Coins** | "币" | 安全、稀薄 | 买地券/装饰 |

**设计意图**（`【推断】`）：
- **脏钱有"持有成本"**（被抢风险）→ 玩家必须"要么花，要么洗"
- **净钱有"获取成本"**（洗钱要时间 + 电缆会被破坏）→ 玩家不会瞬间富有
- **币是"跨赛季"的** → 州末清零时，币是唯一留下的东西

## 3. 玩家旅程：一笔钱的一生

| 步 | 玩家动作 | 发生什么 | 风险 |
|---|---|---|---|
| 1 | 抢劫/卖货 | 获得脏钱（物品或现金堆） | 被别人抢 |
| 2 | 带回基地 | 放进洗钱台 | 路上被劫 |
| 3 | 点"开始洗钱" | 脏钱按 tick 变净钱 | 电缆被破坏 → 速度降 |
| 4 | 洗钱中 | 可随时取回脏钱/取走净钱 | 被入侵 → 洗钱台被撬 |
| 5 | 取净钱 | 进账户 | — |
| 6 | 用净钱 | 买地/买建筑/改装 | — |

**关键体验**：**第 3 步的"开始洗钱"必须是一个有仪式感的动作**（音效 + 点钞机动画 + 进度）。这是玩家"我富有了"的情绪峰值。`【推断】`

## 4. 洗钱的四个乘区（数值骨架）

| 乘区 | 来源 | 玩家感知 | 设计意图 |
|---|---|---|---|
| 模块 | 洗钱台加速件（点钞机） | "我升级了" | 建造投入 |
| 保护 | 聚落公共建筑（bunker/保安） | "这个聚落安全" | **业主↔居民正和** |
| 数量 | 囤积的脏钱量 | "我囤得多洗得快" | 反挂机（要么快进快出，要么囤） |
| VIP | 付费 | "我买了会员" | 商业化 |

**"保护"乘区是整个经济最重要的设计**（`【推断】`）：
- 业主建防御 → 居民洗钱快 → 居民更愿意来 → 业主税收多
- **这是唯一一个"业主与居民双赢"的机制**

ROB RUN 的缺陷：`speedByProtect` 的具体数值不知道，但方向是对的。

## 5. 税：不是"收租"，是"抢劫的合法化"

### 5.1 两条税线

| 税 | 谁交 | 谁收 | 收税地点 |
|---|---|---|---|
| **Land tax**（聚落税） | 居民（按洗钱流水） | 聚落业主 | 该聚落的 Debt Collectors' Van |
| **Control tax**（控制税） | 帮派产业 | 帮派 | 帮主所在聚落的 Van |

### 5.2 收税 = 一场公开的抢劫

**原文**（`【原作】`）：
> `tax_collection_safe_description` = "The contents will be placed on the table and **will be available to everyone nearby**."

**设计意图**（`【推断】`）：
- 如果税直接进账户 → 业主"躺收" → 没有博弈
- 如果税掉在桌上 → 业主收税时**必须冒被抢的风险** → 收税变成"公开的抢劫窗口"

**这是整个经济系统最妙的一处**：把"收税"从"被动收入"变成"主动冒险"。

### 5.3 收税状态机

```
累积期（4 小时？） → 生效 → 业主走到 Van → 长按 → 现金堆 → 拿走 → 冷却（1 小时？）
```

**关键参数**（`【未知-服务端】`，推断值）：
- 税生效延迟：4 小时
- 税额累积上限：24 小时
- 收税长按：8 秒
- 收税冷却：1 小时

## 6. 现金锁：防止"边收边涨"

**问题**：税是流水抽成，流水实时变化。如果收税时还在涨，会重复发放。

**解法**（`【原作】`）：
1. 收税时先"锁住当前金额"（`CashLockedAmount`）
2. 重算（`RecalculateSettlementCashDataForTs`）
3. 重算完才发放
4. 期间 UI 显示"Tax amount is being recalculated"
5. **现金锁生效瞬间，强制关闭已打开的税对话框**（`CloseTaxDialogOnCashLockUpdater`）

**设计含义**：**宁可让玩家多等，也不能让钱重复发**。`【推断】`

## 7. "大便堆"事件：用羞辱替代惩罚

**原作**（`【实证】`）：
- `LaunderingPoopMessage(entityId)`
- `MoneyWorkbenchData.PoopPilePlacers : ListData<PublicIdData>`
- `PoopPileNodeView` / `MoneyWorkbenchPoopPileViewUpdater`

**推断语义**（`【推断】`）：
- 洗钱台出了某种"事故"（满了/被打断/被入侵），地上出现一坨"大便"
- **记录是谁导致的**（`PublicId`）
- 别人能看到"这是谁的"

**设计意图**：
- 不用"罚款"（玩家会反感）
- 用"羞辱"（玩家会记住）
- 且**不产生永久损失**（一坨便便，不是扣钱）

> 这是 Kefir 式幽默：**用荒诞表达惩罚**。

## 9. 反作弊与边界情况

| 风险 | 防护 |
|---|---|
| 洗钱台无限囤 | `MaxDirtyCashAmount` |
| 收税时被抢导致重复发放 | 现金锁 + 重算 |
| 小号刷聚落税 | 税基是真实洗钱流水 |
| 现金堆刷钱 | `TakeCash(amount)` 扣减式，服务端权威 |
| 洗钱中退出游戏 | `LastTickTs` 记录，离线继续算 tick |
| 电缆被破坏后不修 | `BrokenCablePenaltyPercent` 让收益降到极低 |

## 10. 测试边界（本系统 26 条）

**洗钱**

1. 放脏钱 → 开始洗 → 按 tick 增加净钱
2. 停止洗钱 → 记录 `LastTickTs`，离线继续
3. 取回脏钱 → 净钱不减少
4. 洗钱台满（`MaxDirtyCashAmount`）→ 拒绝再放
5. 电缆被破坏 → 速度下降（`BrokenCablePenaltyPercent`）
6. 修电缆 → 读条 `RepairBrokenCableDuration`
7. 加速件 → `DirtyCashPerPeriodModifier` 提高
8. `BonusPerAmount` 分段 → 不同脏钱量加成不同
9. 四源加成叠加 → tooltip 显示正确
10. "大便堆"事件 → 记录 `PublicId`，别人可见
11. 洗钱台被撬 → 脏钱/净钱掉落

**税**

12. 聚落有主 → 居民洗钱 → 税累积
13. 税累积到 `TimeToActiveTaxes` → 生效
14. 业主走到 Van → `CanPlayerStartCollection`
15. 长按收税 → 现金堆生成在桌上
16. 现金堆被抢 → 业主损失
17. 收税冷却中 → `CanTakeTax=false`
18. 现金锁激活 → 强制关闭对话框 + "Tax amount is being recalculated"
19. 现金锁到期 → 金额重算完成
20. 帮派税在"帮主所在聚落"收（不是产业所在聚落）
21. 非业主收税 → "You are not the settlement owner"
22. 帮派权限不足 → "Not enough clan permissions"

**货币**

23. 脏钱可在黑市直接花（不洗）
24. 净钱不能直接给玩家（只能账户）
25. 币与净钱不可互换
26. 州末清算：脏钱/净钱/币 各自的处理

## 11. 复刻时的三个"反直觉决定"

1. **收税必须掉在桌上** —— 直觉上"税直接进账户"更省事，但那会让业主躺收，失去博弈。
2. **脏钱可以直接花** —— 直觉上"必须洗才能用"更硬核，但那会让黑市变成唯一出路；允许"不洗也能花"反而让"洗"变成一种**选择**。
3. **用羞辱而不是罚款** —— 直觉上"洗钱失败扣钱"更直接，但"大便堆"这种荒诞反馈更容易被玩家接受和传播。
