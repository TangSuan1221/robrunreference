## 1. 这个系统为什么难

单机游戏里"开箱子"就是"开箱子"。多人游戏里"开箱子"要回答五个问题：

1. 两个人同时开，箱子听谁的？
2. A 开着时 B 能不能关？
3. 一个人能同时开两个箱子吗？
4. 开箱的人掉线了，箱子还开着吗？
5. 箱子被炸了，正在开的人怎么办？

**ROB RUN 用三层锁回答了这五个问题**。`【推断】`

## 2. 玩家感知到的规则（只需要记 4 条）

| 规则 | 玩家语言 |
|---|---|
| **一次只能做一件事** | "我在撬锁，就不能同时捡钱" |
| **箱子可以一起看** | "我们俩可以一起翻这个箱子" |
| **藏身点只能一个人** | "有人占了，等我出来" |
| **钱是抢的，不是分的** | "谁先扣到算谁的" |

## 3. 四类冲突的设计决策

| 冲突 | 决策 | 为什么 |
|---|---|---|
| 同物体同功能 | **共享** | 否则两人开同一箱会互相踢 |
| 同物体不同功能 | **分区** | 引擎盖/后备箱/底盘 各自独立 |
| 同物体互斥功能 | **独占** | 藏身点不能叠人 |
| 同玩家互斥动作 | **角色锁** | 防止"边撬边捡" |

## 4. 三条"反直觉"但正确的定案

### 4.1 抢钱不锁物体

**直觉**：锁住钱堆，一人拿完。
**原作**：扣减式，两人同抢 800 得 500+300。

**为什么**：这是**时间竞争**，不是**系统竞争**。前者有戏剧性（"我抢到了 300"），后者只有挫败（"我没抢到"）。

### 4.2 撬门允许协力加速

**直觉**：一个人撬，其他人等。
**原作**：进度是物件级的，多人撬 = 加速。

**为什么**：让"叫队友一起来"成为真实战术。

### 4.3 读操作零 RPC

**直觉**：所有交互都发服务端。
**原作**：L2 类（储物箱/货架）**不发任何消息**。

**为什么**：这是"单州塞很多人"的关键优化。**别给读操作加 RPC**。

## 6. 测试边界（摘要，完整见既有规格）

1. 两人开同箱 → 不关
2. A 走后 B 在 → 不关
3. 两人抢藏身点 → 第二人被拒
4. 一人同时撬锁+捡钱 → 被角色锁拒绝
5. 抢钱 → 扣减式
6. 三人撬同一门 → 加速
7. 断线重连 → 占用释放
8. 独占物被毁 → 人弹出
9. 交易商排队 → 显示等待
10. 改装三区 → 互不干扰

---

## 7. 复刻时的三个"反直觉决定"

1. **抢钱不锁** —— 锁住更"公平"，但扣减式更有戏剧性。
2. **撬门协力** —— 独占更"真实"，但协力让队友有用。
3. **读操作零 RPC** —— 加 RPC 更"安全"，但会让服务器撑不住。
