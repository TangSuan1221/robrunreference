# D04 · 据点产权（系统策划）

> **对应技术文档**：`../tech/04_据点产权_技术实现.md`
> **标记**：`【原作】` / `【推断】` / `【补全】`

---

## 1. 这个系统要解决的核心矛盾

> **"我的家必须是安全的，但它必须是别人能抢的。"**

这两句话看起来矛盾，ROB RUN 的解法是**把"家"和"地"分开**：

| 对象 | 安全性 | 可掠性 |
|---|---|---|
| **地块本身**（Plot） | 绝对安全（`No one can take away purchased land`） | — |
| **地块里的东西**（建筑/储物/家具） | 不安全 | 可被撬、可被抢 |
| **聚落**（Settlement） | 可买断，业主可收税 | 业主可被驱逐（但需要撬开全部安防） |

**结果**：玩家的"根"（地）不会被拔，但"果"（东西）会被摘。这既给了安全感，又保住了 PvP。`【推断】`

## 2. 两种产权 = 两个玩法循环

### 2.1 循环 A：居民循环（大多数人）

```
赚钱 → 买 Land Plot Title → 租地 → 建家 → 生产/洗钱 → 被抢/被保护 → 继续
```

**关键体验**：**"我有家了"**。这是整个游戏的情绪锚点。

### 2.2 循环 B：业主循环（少数人）

```
攒钱 + 攒 Settlement Title → 买聚落 → 命名 → 招居民（靠公共建筑吸引）→ 收税
  → 被入侵（首当其冲）→ 修防御/升级建筑 → 继续
```

**关键体验**：**"这块地是我的地盘"**。

**两个循环的交点**：业主需要居民（税基），居民需要业主（有主才能进）。**这是一个强制共生结构**。`【推断】`

## 3. 玩家旅程：从"无家"到"有家"到"有地"

| 步 | 玩家状态 | 系统动作 | 文案 |
|---|---|---|---|
| 1 | 无地，想进聚落 | 拒绝 | `realm_notification_player_has_no_home` = "Buy a plot in a settlement first" |
| 2 | 拿到 Land Plot Title（Tier1） | 可租 1 级区的地 | `plot_sale_1_description` |
| 3 | 找有主聚落 | 只有有主的聚落可租 | `You can only rent a plot in a settlement that has an owner.` |
| 4 | 点出租标牌 | 打开租地对话框（房东名 + 条件 + 权益） | `rent_dialog_*` |
| 5 | 确认 | 付出地券 → 成为居民 | — |
| 6 | 想换更高级的区 | 需要 Tier2/3 的地券 | `plot_sale_2/3_description` |
| 7 | 想买聚落 | 需要 Settlement Title + 上限未满 + 区允许 | `realm_own_dialog_condition_1` |
| 8 | 买下聚落 | 命名 → 成为业主 | `settlement_sale_*_description` |
| 9 | 招居民 | 建公共建筑（军工厂/实验室/bunker…） | `building_*_bonus` |
| 10 | 收税 | 到 Debt Collectors' Van | `tax_point` |
| 11 | 遇到赖着不走的居民 | 用 Eviction Right + 撬开全部安防 | `evict_plot_1_description` |

## 4. 数值与门槛（本地真值 + 推断）

### 4.1 已确认的本地事实（`【原作-实证】`）

| 项 | 事实 |
|---|---|
| 价格单位 | **物品清单**（不是钱） |
| 价格档位 | Tier 1/2/3 × 5 种用途（地块/聚落/聚落建筑/地块建筑/本地迁移） |
| 地券档位 | Tier 1/2/3，与区 Tier **必须匹配** |
| 聚落上限 | `OwnedSettlementConfig.MaxCount`（值未知） |
| 驱逐成本 | 1 件物品（`PriceItem`）+ 读条（`CastTime`） |
| 驱逐前置 | 撬开目标**全部**安防系统 |
| 驱逐收益 | 业主可保留一部分资产 |
| 聚落命名 | 3 字符起，拉丁字母+数字+空格，不可纯数字/首尾空格/连续空格/重名 |
| 地主面板 | 双页签（Settlements / Robbing） |

### 4.2 推断的数值框架（`【推断】`，用于复刻起步）

| 参数 | 建议值 | 理由 |
|---|---|---|
| Tier1 地券 | 任务/教程给 1 张 | 保证首次进游戏 15 分钟内能安家 |
| Tier2 地券 | 约 3 倍 Tier1 价格 | 让"升级区"成为中期目标 |
| Tier3 地券 | 约 10 倍 Tier1 | 终局内容 |
| 聚落价格 | 约 20 倍 Tier1 地券 | 业主是"重资产"玩法 |
| 本地迁移折扣 | 原价 50% | 鼓励在区内换地而不是跨区 |
| `MaxCount` | 1 | 既有文档推断；避免地产化 |
| 驱逐读条 | 10–30 秒 | 足够被反杀 |
| 驱逐保留比例 | 30% | 业主有利可图但不至于"清空" |

## 5. 四个必须讲清的设计决策

### 5.1 为什么用"物品"而不是钱

| 好处 | 说明 |
|---|---|
| 供给可控 | 地券可以从掉落/任务/商城/战令多处产出，不动经济数值就能调节 |
| 天然市场 | 地券是可交易物品 → 玩家之间自动形成"地价" |
| 通胀隔离 | 现金通胀不会推高地价 |
| 文案更好 | "你的地契等级不够"比"你的钱不够"体感好 |

`【推断】`（与既有文档一致，本文件补充：**价格本身也是物品清单**，不只是"买地券"）

### 5.2 为什么聚落主可以"收税"但不能"随意踢人"

- 如果业主能一键踢人 → 居民不敢投资建家 → 聚落空心化。
- 如果不能踢人 → 恶意占坑的人无法清除。
- **ROB RUN 的解**：踢人可以，但必须**撬开他家全部安防** → 踢人=打一场硬仗。

**设计含义**：驱逐是"武力行为"，不是"管理行为"。这让"业主"更像"帮派老大"，而不是"物业经理"。`【推断】`

### 5.3 为什么地块"不可被抢"但"可被驱逐"

- 地块不可抢 → 玩家敢把最好的东西放家里。
- 地块可被驱逐 → 业主有终局手段清理恶意居民。
- **两者不矛盾**：抢是"拿东西"，驱逐是"换人"。`【推断】`

### 5.4 为什么买聚落时要"当场命名"

- 命名是**产权转移仪式**的一部分：从"系统持有"变成"你的地盘"。
- 如果允许先买后改名，会出现"买了不命名"的空壳聚落，地图上难看。
- 命名校验（5 条）在购买流程里做，**一次拦住所有非法名**。`【推断】`

## 6. 与其他系统的耦合

| 系统 | 耦合点 |
|---|---|
| 建造 | 只有租到地才能建；业主免费拿地 |
| 经济 | 地价/税率都在 `TierParams` 里；物品折算由服务端算 |
| 税 | 业主收税；税率由区 Tier + 公共建筑决定 |
| PvP | 驱逐需要撬全部安防；地块本身不可抢 |
| 地图 | 聚落卡片显示归属/税点 |
| 社交 | 业主与居民是强制共生；帮派可以集体入侵某聚落 |
| 元系统 | 教程强制走"租地→建房" |

## 8. 测试边界（本系统 24 条）

**购买聚落**

1. 上限已满 → 拒绝，文案 "{0}/{1}"
2. 区不允许买（`CanBuySettlement=false`）→ 按钮禁用
3. 聚落已售 → "Settlement already bought"
4. 名字重名 → "Name already taken"
5. 名字 <3 字符 → 长度错误
6. 名字纯数字 → 纯数字错误
7. 名字含特殊符号 → 符号错误
8. 名字首/尾空格 → 空格错误
9. 名字连续空格 → 连续空格错误
10. 购买成功 → 成为业主、可免费拿地、可收税

**租地**

11. 无地券 → 条件不满足，显示 "{0} ({1}/{2})"
12. 地券 Tier 与区 Tier 不符 → 拒绝
13. 聚落无主 → 拒绝
14. 聚落满员 → "no available plots"
15. 已有地块时再租 → 二次确认（"all contents transferred"）
16. 换租时正在被突袭 → 拒绝（`cant_move_plot_when_raid_lock_active`）
17. 本地迁移（同区换地）→ 走折扣价
18. 队伍中有人无地 → 整队不可进

**驱逐**

19. 未撬开全部安防 → 不可驱逐
20. 无 Eviction Right 物品 → 不可驱逐
21. 驱逐读条中被打断 → 取消
22. 驱逐成功 → 业主获得部分资产

**展示**

23. 地主面板双页签切换正常
24. 聚落卡片：有主/无主/税点三态正确

## 9. 复刻时的三个"反直觉决定"

1. **地块不可抢，但聚落可驱逐** —— 直觉上"要么都可抢，要么都安全"，但"地"是安全感来源，"人"是管理问题，必须分开。
2. **驱逐要撬全部安防** —— 直觉上"业主应该有管理权限"，但那会让居民不敢建家。**把管理权变成武力成本**。
3. **买聚落当场命名** —— 直觉上"名字可以后改"，但这会让"买而不建"的空壳聚落污染地图。**命名即产权仪式**。
