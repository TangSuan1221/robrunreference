# D09 · 防御、突袭与警报（系统策划）

> **对应技术文档**：`../tech/09_防御突袭与警报_技术实现.md`
> **标记**：`【原作】` / `【推断】` / `【补全】`

---

## 1. 这个系统的核心命题

> **"被入侵必须是可预见的、有代价的、可反击的。"**

如果入侵是"随机天灾"，玩家会弃游；如果入侵毫无代价，玩家会无限刷。ROB RUN 用三件事平衡：

| 要素 | 作用 |
|---|---|
| **防御点** | 让"撬开"需要投入（时间/道具） |
| **Raid Lock** | 让"被入侵"变成一段确定的时间窗 |
| **警报** | 让"防守方"有反应机会 |

**设计铁律**：
> 入侵者的期望收益 ≈ 防守方的期望损失，**且两者都必须大于零**。

---

## 2. 三个角色的视角

| 角色 | 看到什么 | 想什么 |
|---|---|---|
| **房主** | 警报、防御块状态、锁倒计时 | "谁来了？我要不要上线？" |
| **入侵者** | 防御块（看不到模块配置）、可撬提示 | "要带几个解码器？" |
| **路人/帮派** | 地点警报、帮派日志 | "要不要去帮忙/去抢？" |

**信息不对称是关键**：
- 入侵者**看不到**防御块的模块配置（`PublicData` 只有锁/状态/空槽标志）
- 房主**看得到**全部（`PrivateData`）

→ **入侵者必须"试探"**，房主必须"赌"。`【推断】`

---

## 3. 攻防流程（完整时序）

```
① 入侵者靠近别人家
② 看到防御块（Public：显示防御点档位？/是否已被撬）
③ 决定用哪级解码器 → 开始撬（Raiding）
④ 撬的过程中：
   - 防御块状态 Active → Raiding
   - 触发警报（按警报器档位）
   - 房主/地点/帮派收到通知（有延迟）
⑤ 撬开：
   - 防御块 → Raided
   - 房主进入 Raid Lock（不能编辑/不能搬家）
   - 入侵者可以进建筑、撬容器
⑥ 结束：
   - 入侵者离开 / 被反杀 / 警察到
   - Raid Lock 到期 → 房主恢复
```

`【实证：状态/字段；推断：时序】`

## 4. 数值设计：单轴对抗

### 4.1 为什么用"单轴"而不是"血量/伤害"

| 方案 | 优点 | 缺点 |
|---|---|---|
| 血量/伤害 | 直观 | 打一半白打，挫败感强 |
| **单轴（Defense vs Breaching）** | **可预算**：出发前能算"要带什么" | 需要数值设计精细 |

ROB RUN 选单轴（`[实证]`：双方字段都叫 `DefensePoints`），好处：
- 入侵者能在出发前算出"我这级解码器能不能撬动"
- 防守方能算出"升一级模块要多花多少"
- 不会出现"打了一半白打"

### 4.2 破门时间公式（`【推断】`，原作未给出具体公式）

```
T(秒) = clamp( BASE / (1 + k·(Breaching − Defense)), T_min, T_max )
  BASE = 120s, k = 0.35, T_min = 25s, T_max = 900s
若 Breaching < Defense → T = T_max（打不动）
```

**校验**：3 档解码器 × 3 档模块 = 9 种组合，T 落在 25–900 秒，跨度 36 倍 → "要不要来"是真决策。

### 4.3 防御点的三段叠加（`【实证】`）

```
DefensePoints = 基础值 + 普通模块 + 聚落公共建筑加成
```

**关键设计**：**聚落公共建筑（Bunker）给所有居民的地块加防御**。
→ **业主建 Bunker → 居民更安全 → 居民更愿意来 → 税收多**
→ 这是"业主-居民"第二个正和机制（第一个是洗钱保护加成）。

## 5. Raid Lock：把"瞬间"变成"窗口"

### 5.1 为什么需要锁

如果没有锁：
1. 房主收到警报 → 上线
2. 把所有东西塞背包 / 拆建筑
3. 入侵者进来发现是空的

→ **PvP 死掉**。

Raid Lock 的作用：**在"被入侵"期间，房主不能编辑/搬家**。入侵者有确定的时间窗，房主有确定的救援窗。`【推断】`

### 5.2 锁的边界（`【实证】`）

| 能做什么 | 不能做什么 |
|---|---|
| 上线 | 编辑建筑 |
| 看 | 搬家 |
| 跑 | 拖动物品进出槽位 |
| 捡散落物 | 改布局 |
| 修防御（重置锁） | — |

### 5.3 锁的时长（`【补全】`）

| 段 | 时长 | 理由 |
|---|---|---|
| 突袭中 | 实时 | 撬多久锁多久 |
| 突袭结束后 | +30 分钟 | 给入侵者撤离/房主收拾 |
| 预警 | 90 秒 | 房主可上线但不可编辑 |

## 6. 警报：把"被入侵"变成社交事件

### 6.1 三档范围（`【实证】`）

| 档 | 通知谁 | 代价 | 适用 |
|---|---|---|---|
| 个人 | 只通知房主 | 便宜 | 独狼 |
| 地点 | 全地点所有人 | 中 | 想"喊人" |
| 帮派 | 房主 + 全帮派 | 贵 | 帮派据点 |

### 6.2 延迟是精髓（`【实证】`）

**原文**：`deferred_alarm_title` = "Alarm goes off in"

**为什么延迟**：
- 如果即时 → 房主秒上线堵人 → 入侵者永远失败
- 如果延迟 → 入侵者有"确定的作案时间"，房主有"确定的救援时间"

**这是"博弈"而不是"运气"的关键**。`【推断】`

### 6.3 警报队列（`【实证】`）

- 通知**排队播放**（1 秒间隔），不叠加
- 有**优先级**（`Priory`）
- 三种文案：自己/别人/别人+聚落名

**设计含义**：如果 5 个人同时被入侵，你只会看到"最重要的那条"，不会刷屏。`【推断】`

## 8. 反作弊与边界情况

| 风险 | 防护 |
|---|---|
| 房主被入侵时搬空 | Raid Lock + 六道闸门 |
| 房主被入侵时改迷宫 | Raid Lock + 改建筑配额 |
| 入侵者卡墙 | 传送点 + 服务端碰撞 |
| 警报刷屏 | 队列 + 1 秒延迟 + 优先级 |
| 锁到期客户端不同步 | `RaidLockTs` 时间戳权威 |
| 锁被"重置"刷掉 | `RaidId` + 服务端裁决 |

## 9. 测试边界（本系统 26 条）

**防御块**

1. 防御点 = 基础 + 模块 + 聚落加成（三段都对）
2. 特殊模块不加防御点
3. 防御块三态（Active/Raiding/Raided）切换正确
4. 入侵者看不到模块配置（只看到 Public）
5. 防御块被撬开 → 建筑可进入
6. 防御块被修复 → 状态回 Active
7. `IsSlotsEmpty`（模块槽是否空）正确

**攻防**

8. 解码器等级 < 防御点 → 撬不动 / 极慢
9. 解码器等级 ≥ 防御点 → 按 `CastDuration` 撬开
10. 撬的过程中被打断 → 进度回退
11. 多人同时撬 → 进度是物件级还是个人级（`[未知]`）
12. 撬开后可进入并撬容器

**Raid Lock**

13. 被撬开 → 房主进入锁
14. 锁中不可编辑（文案正确）
15. 锁中不可搬家（文案含剩余时间）
16. 锁中可上线/可跑/可捡
17. 锁到期 → 自动解除
18. `ResetPlotBuildingRaidLockTimeMessage` 可重置
19. 锁结束发埋点（`NeedSendRaidLockEndAnalytics`）

**警报**

20. 个人警报只通知房主
21. 地点警报通知全地点
22. 帮派警报通知房主+帮派
23. 警报有延迟（"Alarm goes off in"）
24. 多条警报排队，1 秒一条
25. 警报优先级正确（重要在前）
26. 三种文案（自己/别人/别人+聚落名）各自正确

## 10. 复刻时的三个"反直觉决定"

1. **攻防用单轴，不用血量** —— 直觉上"血量+伤害"更直观，但"打一半白打"的挫败感会杀死 PvP。
2. **被入侵时冻结编辑权** —— 直觉上"房主应该能自救"，但"自救=搬空"会让入侵者永远白来。
3. **警报要延迟** —— 直觉上"即时通知"更友好，但那会让房主秒上线，入侵者永远失败。
